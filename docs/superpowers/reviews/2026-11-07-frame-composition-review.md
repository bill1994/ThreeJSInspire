## 一、画面构成评审结论

整体成立：竖幅画布（设计意图，见 roadmap B3「竖屏窄水平 FOV」）、地平线在画面
约 40% 高度、飞机居中偏下。以下按严重程度列问题。

### P1（阻断级）太阳光路渲染成黑洞

本应是金色亮带的太阳镜面反射区，渲染成一个平滑圆形暗盘：核心近黑（实测像素
(6,2,0)，核心内有一粒琥珀色 glint 亮点），外圈紫蓝色环（实测 (5,0,118)，绿通道
归零）。黑洞顶部被海平线整齐切掉。它直接毁掉黄昏海景最重要的视觉锚点。

已确认的事实（每条都有直接实验或像素证据）：

1. 黑洞位于太阳盘正下方，方位角严格对齐（一帧实测太阳盘 x≈540、黑洞中心 x≈545）。
2. `?sun=az,el` 把太阳挪出画面（150°/270°），黑洞随之消失。
3. `?puff=0` 关近景云，黑洞仍在，且跟着新太阳位置——不是云、不是云影。
4. `?sea=0` 关海面，黑洞消失——由海面渲染产生。
5. 运行时把四个海面网格的 `colorNode` 整体换成常量 1（纯白），黑洞消失——
   **由海面片段颜色图（colorNode）画出**；不是几何破洞（背景色 (26,16,48) 与
   黑核不符；且 `?sea=0` 证明穹顶水下部分是亮橙色，破洞会透出橙色），
   不是后处理，不是独立物件。
6. `?sea=debug` 假色模式下同一区域正常发亮——几何与分档无问题，毒源在正常模式
   的最终合成（`src/sea/material.ts` 的 shaded/withRoad 链）。
7. 静态排查：合成链每一项都是加法或与正值的 mix（`src/sea/material.ts:224-303`），
   `SKY_STOPS` 低端是暖橙（`src/palettes.ts:71-76`），`HORIZON` 常量全是小的正值
   （`src/horizon.ts:15-53`）；IFFT CPU 自检通过（`__porco.qa.selfCheck()` = 3e-5）。
   **源码层面的数学不可能产出黑色**——通道比例破坏（绿归零、红反而出现）指向
   GPU 运行时的 NaN/异常值，而不是任何合法颜色的变暗。
8. 「黑洞跟随太阳」有一个未闭合的漏洞：`?sun=150/270` 是隔几分钟的独立加载，
   若异常随时间闪烁，相关性可能是巧合。干净的实验是同一会话内只翻转海面的
   sun uniform——尚未完成。

## 二、黑洞根因二分（已在旧代码上定案；代码随后被并行重写）

方法：结构性删除/替换最终合成中的单项（不是乘 0——0×NaN 仍是 NaN），每次编辑
触发 vite 整页重载后截图，并对同屏位置采样像素比对。**全部实验帧都跑在
2026-11-07 上午的旧调色板与旧 material.ts 上**（见第三节），结论自洽：

| # | 状态 | 结果 |
|---|---|---|
| 1 | colorNode 换成常量 1（纯白） | 黑洞消失——毒在片段颜色图 |
| 2 | `?post=0` 关后处理，材质复原 | 黑洞仍在——与后处理无关 |
| 3 | `withRoad` 移除 `glitter*glint` 加项 | 黑洞消失——毒随 glint 加项走 |
| 4 | spec 换常量 1（保留 glint 加项） | 黑洞扩大成整片楔形（太阳一侧全黑） |
| 5 | gate/mask 链换常量，金色×1.5 | 全海面 G 通道归零 (0,0,115) |
| 6 | 加纯绿 (0,1.5,0) | 全海面 G=0，出现紫斑 |
| 7 | 加纯绿 (0,0.5,0) | G 反向下降（96→31，R/B 分毫不动） |
| 8 | 隔离：`bandCol.add(绿0.5)` | **加法正确**，海面正常变亮 |
| 9 | `shaded.add(绿0.5)`（天空反射混合保留） | 基底正常变亮，但亮反射区出品红色斑块（G 被杀） |

定案（经验层面）：**毒不在 glint 的数值链（pow/max/smoothstep 全部洗清），
也不在金色数值本身，而在「色带 mix 链的结果 + 大数值加法」的组合**——同一个
加法，加到 `bandCol` 上正确，加到 `mix(bandCol, skyColor, 0.45)`（及其泡沫混色）
上就表现出减法/通道湮灭。表现为：任一通道值被抬过阈值后，该通道在输出中
归零或反相。glint 只是把路内数值推过阈值的那只手，所以黑洞沿太阳光路分布。
琥珀亮点（黑洞中心的暖色残粒）与 (5,0,118) 的紫环都是同一机制的部分通道残影。

编译层机制（TSL→WGSL 里 add 如何在特定图形态下变成减法）**没有定案**——
原因见第三节：代码在实验中途被并行重写，继续在将被整体替换的 material.ts 上
追编译器层机制不值得。给重写者的一条实用警告：**新模型（Schlick Fresnel ×
天空色 + Beer-Lambert 体散射）同样会产出 >1 的通道值**，第 5–7 号实验的
「通道值过阈值即湮灭」现象是渲染管线的性质，不是旧图的巧合——重写后请用
「加一个常量绿」的冒烟测试复测一次（第 6/8/9 号实验照抄即可）。

## 五、穿云白雾（whiteout）机制与观感评估（2026-11-07 补）

触发链（自上而下全链路已读）：

1. 每帧 `cloudProximity01(camera.position, blobs)`（`src/in-cloud.ts:50`）：
   相机对每朵 puff 椭球归一化距离，云面(d=1) 接近度 1、d=2 为 0（smoothstep）。
2. 滞回状态机（`src/game.ts:565-567`）：prox > 0.999 置进云、< 0.985 置出云，
   中间保持，防贴云面闪烁。进云状态同时喂给 director（FOV kick / trauma）与台词。
3. 白雾值 `whiteout01(prox) = prox × 0.6`（`src/in-cloud.ts:37,68`），封顶 0.6。
4. 渲染端是一个 DOM 覆盖层：`div.porco-whiteout`，全屏米色 `#e8dfd6`，
   直接写 opacity（`src/hud.ts:96,114,302`）——注释自认「DOM layer, not volumetrics」。

实况验证：用 `?pos=` 把飞机放进云团中心，白雾 opacity 到 0.6 满值，
画面为全屏均匀浅粉纱，云瓣不可见。

「假」的四个根源（按影响排序）：

1. **云在脸上消失**：`PUFF_FADE_NEAR/FAR = 3/12`（`src/puff-field.ts:51`）让云瓣
   在相机 3-12 m 内淡到全透——钻进去的瞬间可见的云全部退场，只剩平色纱。
   **【2026-11-07 体积感 pass 后已失效：现为 1.2/10、下限 0.3 软墙，见下文】**
2. **纱与视向/太阳无关**：逆光穿云应金色刺眼、背光应灰紫，现在是固定单色。
   **【已失效：`veilTintCss` 按视线-太阳夹角混色，向日暖米 #ffe9c4、背日灰紫 #cfc6da】**
3. **纱与云内密度无关**：线性接近度映射，进云后恒定 0.6，没有浓淡剖面、
   没有云隙节奏、没有颗粒流动。
   **【部分失效：现场瓣软墙 + 兜底瓣提供云内结构，纱封顶降为 0.45 只做兜底】**
4. **触发体比可见云大**：椭球 half 来自整朵 bbox，d=2 起就有雾——看得见云之前
   已经蒙纱。
   **【已失效：白雾封顶 0.45 后远处薄雾不再显眼；椭球触发几何保留】**
