# 开局抬头的上方云覆盖

## 原因与改动

此前固定远景只覆盖约1.5–7°的低空地平线，世界背景云也主要集中在较低仰角；近景 puff 为避免贴脸生成而限制在远端，因此开局抬头时上方缺少云。

- 新增10张世界锚定的中高空背景云片，7张分布在32–49°，3张在71–76°，方位、距离和大小错开。前上方的云在正常爬升镜头内就能进入画面。
- 云心距离开局位置约4.7–6.4km，复用已有中型云烘焙贴图，不新增体积云 raymarch 或烘焙目标。新增云片有额外绘制成本；本轮未作手机性能验收。
- 上方云使用完整三维距离控制透明度和近端回收，飞到云下方时不会因水平距离接近0而突然隐藏或搬走。
- 上方云之间以三维方向和有效轮廓范围检查间隔，不再把“同方位、不同仰角”误判为重叠。保持原有低空云与 puff 的布局、净空和穿云规则。
- 开局云已准备好；之后仍采用屏幕外准备、雾后回收。视线转动不会生成或旋转整层云。

## 验证

- 81个测试文件、860项测试通过；前上方云仰角最后由38°微调到32°后，16项相关测试及最终构建再次通过。
- `scripts/upper-cloud-probe.mjs` 检查默认入口、实际上拖爬升、四个方向35°仰视、70°与85°仰视：10张云开局均准备完毕，转头期间世界坐标与generation不变，无浏览器错误。
- 证据：`artifacts/sea-upper-sky-final-2026-11-20T09-37-44-798Z/`。
- 长距离场景探针覆盖60km移动：视差存在、可见云世界锚定、58次回收均在不可见处且新位置在远端；飞行期间没有重新拷贝云烘焙贴图，浏览器无错误。
- 证据：`artifacts/bg-flight-upper-sky-recycle-2026-11-20T09-38-32-711Z/`。

这是一层保留晴空的稀疏上方云，不保证任意飞行位置的每一个像素都被云覆盖。
