# 渲染性能初步优化（测量基线 + 方向排序）路线图

> **For agentic workers:** 本文件是**阶段级路线图**（沿 `2026-11-12-day-night-planB.md` 先例）——固化测量口径与瓶颈排序，定优先级与验收门；**每一项开工前按仓规另出任务级 fail-first 计划**（writing-plans），步骤不在此展开。

**Goal:** 把 2026-11-12 的实测固化成可执行的优化路线：先砍 puff 云的 overdraw（掉帧元凶），再谈后处理与海面片元，最后是纹理内存。

**Architecture:** 三层——①**测量口径**（焦点陷阱、vsync 地板、p95 才是信号）②**瓶颈排序**（puff > post > sea ≈ dome）③**每项独立验收**（同一口径复测 + 基准帧 A/B 不许退化）。

**Tech Stack:** TypeScript 5.5 · three 0.186.0（WebGPU/TSL）· Vitest 2.1 · `qa.frameStats()`（600 帧窗口）· dsh 内置浏览器（WebGPU 真机）

**Spec:** 无独立设计稿。本路线图的输入是 2026-11-12 的一次实测会话（主人报「跑起来渲染压力有点大」），数据与结论全部落在 §1。

## Global Constraints

- **默认逐位不变**：任何优化都必须给出「关掉开关 = 与原画面逐位相同」的证据，或在基准帧 A/B 里说明哪些像素预期改变、为什么。
- **不许靠降分辨率蒙混**：渲染缩放与「风格化清晰」冲突，不在本路线图内。
- **验收只用一种口径**：§1.1 的协议。换口径 = 换标尺，数字不可比。
- WebGPU-only，three 0.186.0；每项落 `perf(scope):` 提交。
- 观测工具只读：`qa.frameStats()` / `renderer.info`，不为优化新增生产代码路径。

## Review Focus

1. **焦点陷阱**：`document.hasFocus() === false` 时 Chrome 节流 rAF，帧时间会假性变好或变差——今天第一轮测量就栽在这里（13.9 与 20.8 互相矛盾）。每段测量前必须先断言焦点。
2. **vsync 地板**：13.9 ms ≈ 72 fps 是本机地板。任何「降到 13.9」只代表「够用了」，**不能**当作「省了 N 毫秒」的证据；量化收益必须看 p95 或 CPU 侧计时。
3. **局部优化被全局掩盖**：四层里任关其一都能回到地板，说明系统卡在临界点。单独优化一层可能测不出变化——验收要成对关/开，不能只看绝对值。
4. **画面退化**：puff 减量/缩尺寸最容易「省了性能、丢了体积感」；海面简化最容易「省了片元、裂了地平线」（DOME-01 的教训）。每项都要有基准帧。
5. **移动端内存**：81 MB 纹理今天没成为帧时间瓶颈，但在手机上会先撞内存墙——不要因为「桌面跑得动」就把它排到最后。

## 1. 测量记录（2026-11-12）

### 1.1 协议（复测必须照抄）

- 环境：dsh 内置浏览器（WebGPU 真机），`http://localhost:5173/?pos=0,60,-300`
- canvas 锁 `434×772`，`quality=high`，每段 **12 秒**（`qa.frameStats()` 窗口 600 帧 ≈ 12.5 s）
- 每段先 `document.hasFocus()` 断言为 `true`；失焦时先点击画布再测
- 读 `p50 / p95 / mean / renderer.info.render.drawCalls / memory.total`

### 1.2 数据

| 配置 | p50 (ms) | **p95 (ms)** | drawCalls |
|---|---|---|---|
| 基线（high，全开） | 20.8 | **27.9** | 90 |
| 关海面 | 13.9 | 20.8 | 84 |
| 关穹顶云 | 13.9 | 20.8 | 87 |
| **关近景 puff 云** | 13.9 | **14.1** | 78 |
| 关后处理（bloom+DOF） | 13.9 | **20.6** | 78 |
| 现成 low 档 | 13.9 | **14.1** | 88 |

附带读数：`memory.total = 81.1 MB`，其中 `texturesSize = 81.8 MB`（≈ 全部）。

### 1.3 结论

1. 高档 **20.8 ms ≈ 48 fps**，正好是 72 fps 的 3:2 节拍——GPU 超预算后被 vsync 压到下一档。
2. **puff 云是掉帧元凶**：关掉它 p95 27.9 → 14.1（峰值省 13.8 ms）。后处理次之（-7.3 ms）。
3. **四层任关其一都回地板**：系统卡在临界点，不存在单一独占瓶颈。
4. **low 档已经能治**（p95 14.1），和「关 puff」等效。
5. 海面关掉省 6.9 ms（p50），但**这份成本主要不在远端**——远处透视压缩后像素占比很小，贵的是近处全屏片元（Fresnel + 反射 + 太阳路 + 三级雾）。

## 2. 优化方向（按性价比排序）

### P1 · puff 云 overdraw（最高优先）

**证据**：关 puff → p95 27.9→14.1，drawCalls 只少 12。**是片元/叠加成本，不是 draw call 数量**。

**待查（开工前第一步）**：
- puff 的绘制形态（每朵一个 mesh？instanced？透明叠加几层？）
- 屏幕覆盖率与平均 overdraw 层数（可用 `?puff=0` 差分估）
- 尺寸/距离带分布（大朵近景云最贵）

**候选手段**（开工时用数据选，不要全上）：
| 手段 | 省什么 | 风险 |
|---|---|---|
| 距离 LOD（远处降段/降尺寸） | 片元 | 远景云变方 |
| 减最大朵尺寸 / 减数量 | 片元 | 体积感流失 |
| 合并成更少的大 quad | draw call（当前不是瓶颈） | 视差死 |
| 早退（被遮挡/极远处直接丢弃） | 片元 | 需要正确的深度判断 |

**门**：p95 < 16.7 ms；基准帧 A/B 云掩码覆盖率下降 ≤10%，且「云还是云」（目检 + 掩码峰值）。

### P2 · 后处理（bloom + DOF）

**证据**：关掉 p95 27.9→20.6。

**待查**：bloom 的 mip 链层数/分辨率；DOF 的 CoC 采样数；两者是否都能按档位降级。

**候选**：低档关 DOF（视觉收益存疑，开销确定）、bloom 降分辨率半档。

**门**：p95 改善；`?post=` 开关逐位 A/B。

### P3 · 海面片元（不是远端！）

**证据**：关海 p50 20.8→13.9，但远端像素占比小。

**候选**：远环用更简的 shader 变体（跳过反射/太阳路，只留雾 + 底色）；**缩 R3 收益很小，别当主手段**。

**门**：地平线不裂（复用 `analyze_horizon_isolation.py` 的隔离口径）；远海颜色与近海在雾里连续。

### P4 · 纹理内存（移动端前置）

**证据**：81 MB 纹理 ≈ 全部 GPU 内存。

**待查**：海面 FFT cascade 纹理组、云噪声体积纹理、天空 LUT 各占多少。

**候选**：降分辨率、合批、体积噪声降 3D 尺寸。

**门**：`memory.texturesSize` 下降 ≥30%，画面无可见损失。

## 3. 验收门（跨项全局）

1. **口径一致**：所有对比数字来自 §1.1 协议；换口径必须重跑基线。
2. **焦点断言**：任何测量段 `hasFocus === true`，否则该段作废。
3. **成对测量**：优化项与「关掉该层」成对记录，避免被地板掩盖。
4. **画面不许退化**：每项附基准帧（`artifacts/perf-audit/`），A/B 差异必须解释。
5. **默认逐位不变**：新增开关的 item=off 路径与原画面一致（字节级或明确列出预期差异）。

## 4. 不在本期范围

- 降渲染分辨率 / 动态分辨率（与风格化清晰冲突）。
- 缩海面远环作为主要手段（收益小，见 §1.3-5）。
- WebGL 回退。
- 太阳路/云的调色改动（属 toon/day-night 线）。

## 5. 风险与对冲

| 风险 | 等级 | 对冲 |
|---|---|---|
| 优化测不出变化（地板掩盖） | **高** | 成对关/开测量；必要时用 CPU 侧 `performance.now()` 夹 `render()` |
| puff 减量破坏体积感 | 中 | 掩码覆盖率 + 目检双门；先降远处，不动近景 |
| 海面简化裂地平线 | 中 | 复用 DOME-01 的隔离量具 |
| 移动端内存先炸 | 中 | P4 提前评估，别等桌面优化完 |
