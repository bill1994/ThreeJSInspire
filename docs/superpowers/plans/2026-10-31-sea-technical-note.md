# 海面技术说明（2026-10-31）

**目标：** 把「海面像塑料 / 分档几乎不可达 / 满屏碎钻」拆成可复跑的数值与代码位置，给出验收门和候选方向，不含实现代码。**先说结论：** 三对基线里"没有太阳路"这一条在其它截图上复现不出来（§1.1 口径警告），真正稳的缺陷是**分档几何到不了高带**（§1.2）与**碎钻**（§1.5）。

**范围：** 只覆盖 FFT 谱、双域合成、分档几何、太阳路、镜面高光、远场霾。云见 `2026-10-31-clouds-technical-note.md`，天空见 `2026-10-31-sky-technical-note.md`。

**状态：** 分档与高光的分布是**CPU 复算**（同源确定性谱），帧级指标是**已测**。没有 GPU 帧计时，性能结论一律标「未验证」。

## Global Constraints

1. **调色单源**：`SEA_PALETTE`（`src/palettes.ts:82-95`）；`SEA_PALETTE.haze` 必须等于 `SKY_PALETTE.horizon`（`palettes.ts:93-94`，合约见 `palettes.ts:11-12`）。
2. **单一太阳**：`SUN_DIRECTION`（`palettes.ts:17,29-33`）；`sun-road.ts` 的常量与 `sea-fft.ts` 的 TSL 必须读数一致（`sun-road.ts:95-104` 是测试镜像）。
3. **世界坐标采样**：`uv = worldXZ / period`（`sea-fft.ts:589-594,615-616`）。高光钉在世界里，不许回到"跟飞机走的 UV"。
4. **单输出所有者**：海是 `MeshBasicMaterial` 式的 node material，`transparent = false`（742-745），不许把远场交给后处理。
5. **双后端 TSL**：`world.ts:104-114` 已删除 Gerstner 回退，WebGL2 跑道跑同一条 TSL 路径。
6. **`post.ts` 的 bloom 峰值假设**：`sun-road.ts:14-20` 明确"路的峰值不许抬，因为 `post.ts` 的阈值是对着它调的"。改峰值必须同看 `post.ts:54`。

## Review Focus

1. **抬分档会变白片**：`DEFAULT_SEA.amplitude` 的注释（53-55）记着"低太阳 + toon 调色惩罚高浪尖"。
2. **太阳路一抬就碰 bloom**：阈值 0.82（`post.ts:54`），glitter 已有 ×1.5（`sun-road.ts:20`）。峰值抬 2.2× 时高光会进入 bloom。
3. **两域一改就改总波高**：方差拆分（565-582）只有在两域**不相关**时成立，见 §1.3。
4. **远方碎钻与近景碎钻的成因不同**：近景是法线/指数问题，远处是网格欠采样 + 没有距离衰减的高频（§1.5）。
5. **改 `SEA_PATCH_SIZE` 会同时改跟随步长**：`SEA_FOLLOW_STEP = SEA_PATCH_SIZE / TEX_REPEAT`（549-557）、`far-field` 的整周期 snap、以及 `HORIZON.HAZE_FAR = 520` 的推导线（`horizon.ts:14-24`）。

### 1.3 双域合成：方差拆分失效（**复算，新发现**）

`applyTexture` 用**同一个** `config.seed = 1337`（`sea-fft.ts:56,806-813`）建两个域。`buildPhillipsSpectrum` 里 `gauss()` 的调用序列由 `(zi, xi)` 循环顺序与三类跳过条件决定（`150-216`）：`k < 1e-6`、`|mx|,|mz| > nyquist`、`dirDot <= 0`。这三类条件**与 patchSize / windSpeed 无关**（风向两域相同，nyquist 只看 n，DC 只看 bin 0）→ 两个域消耗的随机数完全相同 → **两域的相位完全相关**。

后果（复算）：

| 量 | 设计意图 | 实测（复算） |
|---|---|---|
| 短域 amplitude | `0.34·√0.6 = 0.2633` | — |
| 长域 amplitude | `0.34·√0.4 = 0.2150` | — |
| 合成 RMS | `√(0.2633²+0.2150²) = 0.34`（`565-582` 的推导） | **0.4733** |
| 线性相加（完全相关）预测 | `0.2633+0.2150 = 0.4783` | 与实测差 **1.0%** |

即：**合成的实际波高比设计的 0.34 m 高 39%**，因为两域同相位相加而不是正交叠加。

连带后果：
1. `hNorm` 在 h ≈ ±0.806 m 处就饱和 → 实测 p5 = 0.000、p95 = 0.9918，**上下各约 5% 面积被削平**，可供分档用的动态范围进一步变窄（这是 §1.2 里 `shape` 到不了 0.8 以上的直接原因之一）。
2. 泡沫起点 `foamStart = amplitude × 2.2 = 0.748 m`（`227`）按设计是 2.2σ；在 σ = 0.473 下它只是 **1.58σ** → 泡沫覆盖面积明显高于设计意图。

### 1.5 碎钻：瓣宽 vs 法线倾角（**复算 + 推算**）

- 镜面瓣半宽：`acos(0.5^(1/96)) = 6.88°`；`BROAD` 端 `acos(0.5^(1/26)) = 13.18°`（推算）。
- 法线倾角：`1−ny` 的中位 0.0026 → **4.13°**；p95 0.0265 → **13.2°**；max 0.1206 → 28.2°（复算）。
- 网格：`SEA_PATCH_SIZE 1600` / `SEA_GEOMETRY_SEGMENTS 280`（`549,540`）→ **5.71 m** 一个顶点。
- 短域最细波长：`nyquistGuard 0.85`（`58`）→ `400/(0.85×64) = 7.35 m`（推算）。

两个结论：
1. **瓣宽（6.88°）小于法线的 p95 倾角（13.2°）** → 绝大多数面元"点不到"太阳，只有恰好落进瓣里的少数面元亮起来 → 逐面元二值化 = 碎钻。这不是噪声调参问题，是指数与法线分布不匹配。
2. **顶点间距 5.71 m 小于半个最短波长 7.35 m/2 = 3.68 m 的要求** → 位移本身在欠采样（1.29 采样/波长），近景会看到"移动的板"。

### 1.6 位移只有 y 分量（**已测**：读码）

`material.positionNode = vec3(positionLocal.x, heightNode, positionLocal.z)`（`622`）——只抬高度，**没有水平位移**。Gerstner 的波峰前倾来自水平项，这里不存在；所以浪尖的"朝光面"完全由法线（`625-652`）伪造，而法线又只由高度差分得到（`457-478`）。

### S1 — 分档断点按实测分布重配

**证据（复算）：** `shape` p50 0.3566 / p95 0.6396 / max 0.7855；`lit` 起点 0.54 → 只有 13.14% 面积"沾到"，`lit > 0.5` 只有 0.77%；`crest` 起点 0.88 → **0**。

**候选方向：**
- (a) 抬高度权重（`hNorm·0.62` → 0.75–0.85），把 shape 分布推到 0.2–1.0；
- (b) 收窄 `hNorm` 的映射范围（`0.62h + 0.5` 对应 ±0.806 m，收到 ±0.5 m 量级），等价于提高斜率；

### S2 — 两域 seed 去相关

**证据（复算）：** §1.3，合成 RMS 0.4733 vs 设计 0.34（+39%），与"完全相关"预测 0.4783 只差 1%。

**验收门：**

### S3 — 太阳路：从"只削"改成"既削也抬"（**先做 S0**）

**证据（已测 + 改判）：** 代码层面 §1.4 成立——`roadGate` 上限是 1.0、下限 0.35，**结构上不可能产生峰**；帧层面的"没有峰"只在 ACES 基线帧成立（`width_frac = 0.000`），当前帧已读到 0.069–0.201。所以这条的**改造理由从"实测缺峰"改成"设计上不产生峰"**，是否值得改由 S0 的受控测量决定。

**候选方向：**
- (a) 路内给一个 > 1 的增益（峰值按 `ratio ≥ 2.2` 反推），路外保留现状的 0.35×；
- (b) 在路内加"连续亮带"项而不是放大逐面元高光：沿太阳方位、随距离展宽（掠射 Fresnel 已在 `672-677`，只是被 `FRESNEL_GAIN 0.15` 压着）；
- (c) 把 `SLOPE_FULL` 调到实测坡度量级，让 `BROAD` 端真正参与（**先按 S4 的结论做 A/B**，它可能把碎钻变成白片）。

**验收门（在 S0 协议下）：** `sea_sunroad_ratio 2.4–3.0` 且 `sea_sunroad_width_frac` 落在 0.03–0.22（参考 0.031–0.220），同时 `sea_sparkle_rel` 不高于同批基线。**不要**把 `ratio ≥ 2.2` 当门——当前帧已到 2.61–3.38，那样等于没有门。

**风险：** 峰值一抬就进 bloom（阈值 0.82，`post.ts:54`）；路的峰值假设写在 `sun-road.ts:14-20`，改动必须同步改这条注释的契约。

**状态：抬峰保留，连续亮带否决（run 2）。** 权威口径（`content_bands.bands()` 的 sea 区，逐列找地平线）实测：

| 配置 | `sunroad_ratio` | `width_frac` | `sparkle_rel` | 过曝像素 |
| --- | --- | --- | --- | --- |
| 基线 | 1.14 | 0.000 | 0.06203 | 0.0000 |
| (a) `ROAD_PEAK` 2.0 | **1.28** | 0.000 | 0.06702 | 0.0002 |
| (a)+(b) 连续亮带 0.55 | 1.29 | 0.000 | **0.02640** | 0.0000 |
| ref-01 | 2.86 | 0.270 | 0.14534 | 0.0870 |

**(a) 保留。** `ROAD_PEAK = 2.0` 把 `sunRoadGain` 的路内增益从 1.0 抬到 2.0，ratio 1.14 → 1.28。收益小但无副作用（过曝 0.02%），而且它修掉了「gate 只有 floor、结构上不可能出峰」这个设计缺陷。`sun-road.test.ts` 里那条 `never exceeds the bare glint it is parameterising` 的契约测试同步改成 `makes the road a peak and keeps the off-road base dimmer`——旧契约正是这条任务要推翻的东西。

**(b) 否决。** 把远场往 haze 色混合 0.55：ratio 只到 1.29，而 `sparkle_rel` 从 0.062 掉到 **0.026**（往雾色混合会抹平高频），等于用 S4 的指标换 S3 的零收益。回退。`BROAD` 26 → 10（放宽镜面 lobe）也试过，ratio 1.28 → 1.29，无变化，同样回退。

**为什么 (b) 注定无效。** `sunroad_ratio` 是「列亮度 98 分位 ÷ 中位」的对比量，需要画面里同时存在「路内」和「路外」。`WIDTH_DEG = 25`（半宽），而竖屏水平 FOV 只有 **36°**——路覆盖了 ±25°，**整屏都在路内，没有路外充当分母**。ref-01 是横屏 91° FOV，±25° 只占 55%，带才成立。把 `WIDTH_DEG` 收到 10° 能造出对比，但那是改「路有多宽」的设计，不是改亮度。

**结论：`sunroad_ratio 2.4–3.0` 这条门在竖屏构图上不可达。** 与 K1（ramp 暗端）、K2（暖带彩度）、T4（云分面）同源——参考的横屏宽视野和现场的竖屏窄视野不该用同一把尺子。
