状态：**A 消融完成，B/C 已有第一轮降噪候选和桌面验证，但风格化目标尚未达成；15 ms 性能目标尚未稳定达到。默认仍为 legacy。** 用户看过后反馈观感有所改善，但尚无与云一致的 stylized 风格；后续应继续推进明暗块面、柔硬边缘与太阳倒影的形状组织，不能把本轮降噪记为 B/C 最终完成。2026-11-17 晚间执行记录见 [海面候选验证报告](../reviews/2026-11-17-stylized-sea-review.md)。用户已认可 bg-cloud，认为新版 puff 的穿云体验良好、颜色已接近可接受。本文件接续 `../specs/2026-11-17-alignment-status-handoff.md`，涉及冲突时以当前代码和下面的实测说明为准。

## 1. 本轮目标与范围

把海面调整到能与已认可的云同处一幅画：清楚的大明暗块面、克制的碎反光、柔和而有层次的色彩、能读出太阳方向的倒影。参考 Zelda / Ghibli / painted-valley 的画面组织，不以复刻某个未验证的着色算法作为目标。

保留 FFT 波浪运动、世界坐标锚定、环形网格、飞行速度感、天空和太阳联动。先改着色组织，只有证据表明运动本身有问题时才调整波谱。暂不处理陆地、飞机、玩法或无关历史文件，也不继续重做已认可的云形状。

## 2. 云阶段的可复现状态

### bg-cloud

- 已修复二分求交中间值的 TSL 求值问题：`mid` 在进入条件分支前用 `.toVar()` 固定，避免生成的 WGSL 在另一个分支读取错误的中间值。这是大理石状异常的一项实际根因，不能仅归因于噪声太多。
- 用户认可的组合是 `bglook=form&bgshape=legacy&bgwrite=replace`：保留原形状，用宏观形体参与着色，替换写入烘焙条带，避免旧像素与重复 alpha 混合的干扰。
- `cloud-lab.html` 用于固定机位、太阳和推进帧数的对照。

### puff

- `pufflook=volume` 从原有瓣形构造密度体，减少穿入后可见的 mesh 内壁；保留原形状来源和布局。
- 第二轮缩窄密度边缘，并分别处理云外的厚实感和云内消光，保留用户认可的穿云体验。
- 使用 bg-cloud 的调色映射常数与宏观明暗逻辑，阴影采样使用平滑的宏观密度，减少细碎的着色边界。
- puff 与 bg-cloud 不必逐像素同色。距离霾、太阳相对方向、体积积分与背景云表面着色的差异都会影响结果；不能把余下色差全部解释为距离。海面阶段不再据此强行统一两种云的透明度。
- `puff-lab.html` 提供云外、云内、出云、遮挡、飞行和性能对照。

**默认入口尚未切换到上述新风格。** bg 的求交修复已经进入现有路径；form/replace 与体积 puff 仍需参数开启。海面验收应使用以下完整组合，避免拿旧版云做对照：

```text
/?bglook=form&bgshape=legacy&bgwrite=replace&pufflook=volume
```

需要冻结画面时附加 `qa=frozen&toon=0&dof=0&todspeed=0`，使用 QA 接口固定推进 300 帧；不要把 `qa=frozen` 链接当作正常飞行入口。`cloud-lab.html`、`puff-lab.html` 是本地 Vite 调试页，不等于默认构建的发布入口。

### 已有验证与性能边界

- 当前云代码通过 71 个测试文件、795 个用例、TypeScript/Vite 构建及 smoke。构建仍有既有的大 bundle 和混合静态/动态导入提示。
- 同一桌面、448×797 CSS 视口、high、侧向太阳 80°/8°、bgq256、关闭 DOF，完整飞行更新加渲染短测：旧 mesh p50/p95 为 8.1/12.1 ms，新体积 puff 为 9.0/12.4 ms。
- 方法：从固定 300 帧状态开始，10 次预热、30 次采样，每次等待 WebGPU `queue.onSubmittedWorkDone()`。这是包含 CPU 提交与 GPU 完成的墙钟时间，不是纯 GPU 耗时，也不是持续 FPS 或手机性能保证。
- 原始截图与日志留在仓外本机 `D:/stylize-plan/puff-review/`；上述数值是历史记录，新设备需重新测量，不把本机文件当成 CI 依赖。

## 3. 海面的源码事实与待验证假设

当前海面是包含物理启发项和美术调参的混合模型，不是完整的物理真实模拟。

| 位置 | 当前事实 | 本轮意义 |
| --- | --- | --- |
| `src/sea/cascades.ts` | 长波 128–1024 m、碎浪 32–128 m，另有合入同一格点的 4–27.5 m 细波 | 不能按“尚无细波”去增加噪声；旧注释对此有滞后 |
| `src/sea/material.ts` | FFT 位移、分环 mip 与接缝过渡；片元叠加波面斜率及 4 m 周期细节法线 | 先区分几何起伏、反射法线和微细节的贡献 |
| `src/sea/water-shading.ts` | `SLOPE_GAIN=14`；连续水体/波峰着色、Fresnel 与距离霾 | 放大的法线和高对比反射可能共同造成碎亮纹，需要隔离实验验证 |
| `src/sea/material.ts` | 反射直接调用天空的 `skyColorTsl` | 色源已共享；优先处理反射形状、频率和对比度，而非另造一套天空颜色 |
| `src/sea/sun-road.ts` | 太阳倒影连续项、闪点及分档亮度预算 | 保留方向与亮度约束，试验更连贯的倒影组织 |
| `src/sea/bands.ts`、`foam.ts` | 屏幕尺度细节衰减、Jacobian 泡沫；旧高度色带仅作 debug | 不能把旧四档高度色带直接当成最终卡通方案 |

当前判断是“信息过碎、反射主导画面”的可能性较大，但尚未做海面逐项消融，不能提前认定某一个系数就是唯一根因。

## 4. 分阶段实施

### A. 建立可比较基线

1. 新增一个本地 `sea-lab.html`，复用主场景与 QA 接口；固定机位、太阳、种子、推进帧数、画质及上述云组合。
2. 增加参数 `sealook=legacy|painted`，默认保持 legacy；2026-11-17 晚间已实现。只维护一套海面渲染路径和一套候选配方，不扩散永久实验预设。
3. 临时诊断按顺序隔离：细节法线、细波对反射的影响、总斜率增益、天空反射、太阳倒影、泡沫。每次只改一个因素，记录其视觉作用；诊断不等于最终把该项删除。
4. 留存原始外观和完整场景性能基线，并核对上表中的滞后注释。

交付：同条件基线图、贡献判断、优先调整项。确认问题来自哪一层后进入 B。

### B. 先做大形与反光收敛

1. 保留几何位移，尝试让反射法线弱化细波和微细节，主体起伏仍来自原波场。
2. 从现有合并斜率能否满足要求开始试验；若需要单独控制细波，先评估现有采样/低通方案。不要为了拆频直接新增一套 FFT 或渲染通道。
3. 对水体、波峰和反射形成少量可读的宽明暗区域，过渡保持柔和。阈值如有引入，必须随屏幕尺度抗锯齿，运动时不能跳档或闪烁。
4. 近处保留速度感，中景降低杂乱反光，远处逐渐收敛到天空。保留现有细节屏幕足迹衰减、网格接缝与距离霾逻辑。

交付：一个 `painted` 候选。先判断“海是否安静、清楚且仍在流动”，不同时调整所有色值。

### C. 调色、太阳倒影与泡沫

1. 继续通过 `src/palettes.ts` 取色：海体偏冷、受光和太阳倒影偏暖，与云属于同一光照环境。不要直接把云的四种颜色复制到水面。
2. 将太阳倒影组织成方向明确、断续但有连贯性的亮面；适当减少尖锐闪点。形状随波面、视角、太阳移动，避免屏幕固定条纹或重复正弦线条。
3. 保留太阳倒影与 bloom 的预算约束，复核 high/low 与速度增强项。不得靠提高曝光掩盖着色问题。
4. 泡沫继续受实际波面压缩/波峰条件约束，作为少量形体提示，避免满屏白噪声。
5. 复查日落、较高太阳和背光，不以单张日落截图替代全场景判断。

交付：颜色、明暗块面和反光统一的一套候选参数。仅在 B/C 无法达到目标且有明确证据时，再评估更大改造；第一轮不引入 SSR、反射 RTT 或额外全屏通道。

### D. 验收与收口

| 维度 | 检查场景 | 通过条件 |
| --- | --- | --- |
| 静态构图 | 当前追飞机位、低空、高空；顺光、侧光、逆光 | 云与海同属一个色彩环境，飞机主体清楚，海面不会被碎亮纹占满 |
| 距离 | 近/中/远景及天海交界 | 远景逐渐安静；无网格环、硬色带、明显周期接缝或天海断线 |
| 动态 | 连续飞行与转向 10–30 秒、加减速 | 波浪保持世界锚定，无纹理滑动、闪烁、阈值跳变；低空仍有速度感 |
| 云与遮挡 | 开启认可的 bg 与 volume puff，完成一次穿云 | 海、飞机和体积云遮挡正确；云内体验不退化 |
| 画质 | high/low、实际画布尺寸和 DPR | 低档保留同一设计意图，不靠禁用整个海面达标 |
| 性能 | 相同设备/分辨率/云/后处理/飞行路线 | 记录完整更新加渲染的 p50/p95，并与 legacy 对比；以总场景 15 ms 预算为目标，未达到时明确记录，不能拿局部静态耗时替代 |

执行相关海面测试；涉及着色公式时同步 JS 镜像并验证连续性、有限值、边界与亮度预算。最终运行 `npm test -- --reporter=dot`、`npm run build`、`npm run smoke` 和 `git diff --check`。不为纯截图偏好堆叠实现镜像式测试。

性能记录必须注明设备、浏览器、实际渲染分辨率/DPR、质量档、云密度、后处理、预热和采样次数。先复用云实验的固定短测比较，再补持续飞行检查；手机未测就明确写未测。WebGPU 使用队列完成等待，旧交接书的 `gl.finish()` 不适用。

用户看过最终对照并认可后，再把单一选定方案设为默认，删除本轮无用的临时诊断。此前 `sealook=legacy` 保持可回退，不清理无关历史文件。

## 5. 实现约束与完成定义

- 当前实际渲染路径是 WebGPU；旧交接书中的 WebGL2 回退描述不能作为已存在能力。
- 使用 TSL；`three/webgpu`、`three/tsl` 继续按现有运行时动态加载约定接入，不引入 `ShaderMaterial` 或 `onBeforeCompile`。
- 调色板保持单源，输出色彩转换继续由 `src/post.ts` 管理，JS/TSL 公式镜像同步。
- 保持 FFT 种子、环形网格/mip 接缝、重定位周期、天空太阳联动和功能局部失败时的降级。
- 本次提交完成的是云实验保存及本计划；海面完成需要 B/C 实现、D 验证与用户视觉认可，不能把“计划已推送”记为海面已完成。
