**Goal:** 从 threejs-inspire 裁出一个干净的新仓库 `0to1`——删除海与云的全部实现、文档、审计产物，保留天穹/飞机/post/HUD/音频/游戏循环基座并全绿跑通，为"重构跟云"（云推倒重做）提供零负担起点。

**Architecture:** 复制现行工作树（不含 node_modules/dist/.git/.superpowers）到 `G:\DSHProject\0to1`，git 重新 init、历史从零开始；在新仓库内按"先删实现、再修接线、最后闸门"的顺序清理；原仓库 threejs-inspire 全程不动。云的重做设计种子（puff-cluster-cloud 两份设计文档）随仓库携带。

**Tech Stack:** 与现仓库一致：Vite + TypeScript + three (WebGPU/TSL) + vitest + Python 审计脚本（脚本不随迁）。

**Spec:** 无独立 spec。本 plan 的需求来源是主人 2026-11-06 的原话："新建一个 0to1 的仓库，把海跟云的实现跟所有相关内容都清理掉，重构还跟云"。**所有推测都集中在下方"待确认假设"一节，执行前必须逐条过。**

3. **形态是复制后清理**，不是新脚手架搬运；git 历史全新，不嫁接旧历史。
4. **叙事文案里的"海"字不删**：本项目是 Porco Rosso 主题的水上飞机故事，subtitles/README 里的剧情性"海"是内容不是实现。本 plan 只删实现与工程文档；README 重写时顺手收敛。
5. **master 的 4/2 分叉与 0to1 无关**，不在本 plan 处理；但 reconstruct 的 14 个未推送提交建议在 Task 0 先推（保命，与 0to1 无关）。

## Global Constraints

- 原仓库 `threejs-inspire` 全程只读：不删文件、不切分支、不 push 之外的任何写操作。
- 新仓库全程在 `G:\DSHProject\0to1` 内操作，禁止反向引用 `../threejs-inspire` 的任何文件（依赖必须重新安装）。
- 删除以"模块整删 + 接线重写"为原则：不留死代码、不留注释掉的尸体、不留空转的 QA 参数。
- 闸门数值沿用现行标准：`npx tsc --noEmit` exit 0 · `npx vitest run` 全绿 · `node scripts/smoke.mjs` ok · 启动条显示 `sky only`。
- 每个任务结束单独 commit（新仓库内），commit message 用英文 conventional 风格（沿用现仓库习惯）。

## Review Focus

- **删海后 `perPixelRadians` 一类被 sky/相机借用的 sea 工具**：main.ts 从 `./sea/lod` 导入了它。预期：借用方要么把函数搬进保留模块，要么就地内联；不允许为了图省事把整个 `src/sea/` 留一半。归属 Task 5。
- **far-field 的双重职责**：它同时负责"天穹每帧跟随相机"和"包裹 puff 场"。删云只能剥掉后半，天穹 tow 必须保留，否则相机飞出天穹画面塌成平色渐变。归属 Task 4。
- **in-cloud 的下游不是只有 HUD**：game.ts 的白雾/相机扰动、subtitles 台词、feel 事件都吃 `cloudProximity01/whiteout01`。删云时这条链要整体拆干净，预期 HUD 白雾节点删除、台词与 feel 中云相关条目移除，不留永远为 0 的假数据。归属 Task 4。
- **smoke.mjs 白名单与实际文件一一对应**：删文件不改白名单会假绿（smoke 检查的文件不存在时行为要先看再改）。归属 Task 5。
- **启动条与 QA 参数的行为一致性**：`?puff=0` 参数删除后，URL 带该参数不得报错、行为等同缺省。归属 Task 5。
