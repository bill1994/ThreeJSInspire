# 昼夜轮转 + 月亮 方案 B（时间轴 + 完整天体）分期计划

> **For agentic workers:** 本文件是**阶段级路线图**（沿 `2026-11-05-land-flight-0-to-1.md` 先例）——定架构、接口、验收门与调色策略；**每期开工前按仓规另出任务级 fail-first 计划**（writing-plans），步骤在此不展开到逐行。

**Goal:** 把「黄昏↔夜第一步」扩成完整的日夜轮转 + 月亮系统：时间轴驱动太阳弧线（飞行中光照自己活），月亮独立可见（盘 → 月光 → 月相），全程不破参考档恒等与单一太阳约束。

**Architecture:** 一切仍从 `skyTrackAt(仰角)` 单源扇出（main.ts syncSun 不动结构）；B 的增量 = ①轨道档位补全（6.97°→正午、−8°→深夜）、②时间轴模块（elapsed 驱动仰角/方位弧线）、③月亮（sky shader 月盘 → 夜间复用 DirectionalLight 当月光 → 月相 SDF）。调色劳动用「程序化派生 + 人工只调主观字段」对冲。

**Tech Stack:** TypeScript 5.5 · three 0.186.0（WebGPU/TSL）· Vitest 2.1 · Python 采集量具

**Spec:** 调研报告 2026-11-11（subagent，结论：现状只有 −8/−4/0/+6.97 四档、无时间轴、月亮零实现）；`plans/2026-11-08-day-night-sky.md`（第一步已落地 + :249 开口清单）；`src/sky-track.ts` / `src/sun-state.ts` / `src/main.ts:309-364` 现状。

## 全局约束

- three 0.186.0，WebGPU-only；不得引入 WebGL 回退。
- **调色单源**：所有外观字段只存在于 `SkyTrackState`（sky-track.ts:44-77），任何新档必须落成同结构 KEYS 条目，禁止旁路调色。
- **单一太阳光源**：只吃 `SUN_DIRECTION` / 活 DirectionalLight，不得新造光源；月光照明只能**复用**这盏灯（期 3）。
- **参考档恒等**：6.97° 列的任何字段不得变值；新档只允许落在 >6.97° 或 <−8° 区间。
- **时间纪律**：一切时间取 `elapsed`（累加 dt），禁 `Date.now()`/`performance.now()`——`?qa=frozen` 下时间轴天然冻结。
- bloom 预算 0.82（sky-color-js.test.ts:150 守卫）；月盘/月光峰值必须压线内。
- 每期独立可验收、可玩；期与期之间不许留半接线状态。

## 已定案的技术决定（R1–R8，动手不再议）

- **R1 时间轴数学**：`tod = (t0 + elapsed × todSpeed) mod 24`（小时）。仰角 `el(tod) = 65° × sin(π × (tod − 6) / 12)`（6 点升、12 点正午 65°、18 点落、夜间负）；方位角 `az(tod) = (tod − 12) × 15°/h + 正南偏移`。不引天文库——风格化项目用简化弧线，误差由调色吸收。
- **R2 时间轴入口**：`?tod=<0-24>` 设初值、`?todspeed=<倍率>`（0 = 静止，**默认 0 = 现状逐位不变**）；qa 加 `setTod(h)` / `setTodSpeed(x)` 杠杆。t0 从 `?tod` 解析，缺省 17.5（现参考档时刻）。
- **R3 月亮轨道**：期 2 月亮与太阳共享时间轴反相走（`moonEl ≈ −el`、`moonAz = az + 180°`），不独立调参；期 3 才给 `?moonoffset=`。月方向作为新的 uniform（`uMoonDir`）随 syncSun 一起推送。
- **R4 调色派生策略（对冲 L 成本的核心）**：新档字段 70% 程序化派生——cloudBands/夜色带从相邻已调档做 hue-shift 插值、霾端点走 `seaHazeEndpoints` 派生（sky-color-js.ts:100-116 现成）、灯光色从 `sunColorFor` 派生；**人工只调** 双 ramp 8 色 + cloudBands 4 色的主观档。派生函数落 `sky-track.ts` 纯函数并单测。
- **R5 档位锚点**：+15/30/45/65°（上午→正午）与 0/−4/−8 之间不插新档；深夜档 −20/−40° 只在期 3。每新档 bloom 预算表加一行（post.ts:46-60 现只测到 40°，需扩到 65°）。
- **R6 月盘渲染**：与 sunDisc 同构的角度阈值盘（horizon.ts:187 形态），半径取真实感 1.5°（太阳盘约 4× 夸张是风格，月亮不跟）；月面用 shader 内两三层 noise 斑驳，不做贴图；亮度锚 0.72 < 0.82（学星点压色做法 stars.ts:21-22）。
- **R7 夜间灯光切换**：`el < −2°` 时 DirectionalLight 平滑转向月方位、换冷色（夜档现值 #304060 基础上乘月光系数）、强度升到 0.25——复用同一盏灯，`syncSun` 内按 el 分支；过渡带 ±0.5° smoothstep。
- **R8 太阳路夜归零**：`sunColorFor` 加夜间衰减因子（el<0 时线性归零），太阳路/云受光项同步熄灭——这是对现状「−8° ≡ 0° 钳暖橙」语义的**改判**，须按仓规留痕（改哪条、谁批、何时）。

## 验收门（跨期全局）

1. 参考档恒等：6.97° 列逐字段不变（既有测试不动即自动守卫）。
2. 镜像对齐：每新档 `skyColorJs` 与 TSL 逐点一致（sky-webgpu.ts:192 双镜像纪律）。
3. bloom：全档全帧 <0.82，预算表逐档有行。
4. 冻结兼容：`?qa=frozen` 下时间轴/月亮完全静止。
5. 联动目检五项（海/云/霾/灯/veil）逐档过，复用昼夜计划 Task 8 Step 5 口径。
6. 文档：INDEX.md:100 的过期状态标注随期 1 一起修；每期完成在 INDEX 登记。

## 风险与对冲

| 风险 | 等级 | 对冲 |
|---|---|---|
| 调色劳动量失控（25 字段 × 6-8 档） | **高** | R4 派生策略：人工只碰 12 个主观色；其余程序化 |
