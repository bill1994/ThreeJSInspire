# 程序化岛群：实施计划与新会话交接

日期：2026-11-20。状态：设计与分阶段计划已整理，尚未开始陆地实现。

## 1. 用户确定的方向

- 小岛群为主，偶尔一座大岛。海边为沙滩，往内过渡到塞尔达／吉卜力方向的草坡、树林，与当前海和云的柔和明暗统一。
- 低空飞过时草向两边弯、树枝与树冠偏转，随后恢复；带起少量草叶或树叶；沙滩产生沙尘。
- 岛屿尺度有最小值与最大值，相邻岛屿间距也有最小值与最大值，布局程序化且返回时一致。
- **最新性能基线：低端电脑和高端手机流畅运行。** 此要求取代此前“中端电脑，手机简化”的讨论版本。
- 使用 WebGPU，优先发挥实例化、着色器动画和 GPU 粒子优势；复杂技术必须有测量依据。
- 分阶段实现，每阶段提供可打开的预览、效果说明与性能证据，再按反馈继续。
- 本会话只写计划，不实施陆地、不提交或推送；新会话收到用户继续实施的指令后从阶段 0 开始。

## 2. 实施策略：从有预算的小样开始

不采用“先无限堆满细节，最后统一删减”。先做一个可游玩、可测量的小岛切片，把海、云、飞机和后处理一起算入预算，再扩展岛群和细节。

画质分为基础档和增强项。基础档必须保留岸线轮廓、草坡色块、树冠体积、近景弯草和少量互动粒子；远处草密度、枝叶细节、粒子数量、动态阴影与反射细节可以降低。手机不能只剩一块没有互动的光滑地形。

性能目标与验收口径：

- 两类目标设备均以稳定 60 FPS 为目标；刷新率高于 60 Hz 时按固定帧率目标比较。30 FPS 只作为热降频或预算不足时的降级保底，不能记录为 60 FPS 验收通过。
- 暂定 60 FPS 档：稳态平均帧间隔约 16.7ms，p95 不超过 20ms；30 FPS 保底档：平均约 33.3ms，p95 不超过 36ms。记录 p99、超过 50ms 的帧和触发原因，不能只报告平均 FPS。
- 以上是项目初始目标，不是实测结果。尚未指定 CPU/GPU、手机型号、系统和浏览器版本，不能声称已在“低端电脑／高端手机”达标。缺少实机时可以继续开发，但验收标注未完成；当前电脑或模拟限速不能替代手机实测。
- 每次记录 CSS 尺寸、绘制缓冲分辨率、DPR、实际渲染后端、画质档及各效果开关。手机控制内部渲染分辨率，不能按原生高 DPR 无限制放大负载。
- 阶段 0 先测无陆地的完整现有场景。若海与云已占满预算，先制定必要的基础档调整，不能假设所有性能问题都来自陆地。
- 预热后至少连续飞行 3 分钟，最终手机验收持续至少 15 分钟观察温度与降频；另外单独记录首次加载、首次进入新岛区的卡顿。
- GPU 时间查询仅在设备支持时使用。CPU 耗时、GPU 耗时与呈现帧间隔分别记录，不能直接相加或把提交耗时当作 GPU 耗时。
- 实例、粒子、驻留块、上传字节、绘制调用和反射对象都要有可观察计数及容量上限；具体上限由阶段 0/1 测量制定，而不是预先承诺百万草或几十万粒子。

## 3. 视觉和尺度的初始提案

以下数值是待预览调参的提案，并非用户已经锁定的规格。

| 项目 | 初始范围 | 说明 |
| --- | --- | --- |
| 小岛 | 直径约 300–800m，约占数量 80% | 主体，以草坡、少量树林与水道为主 |
| 中岛 | 800–1400m，约 15% | 较长海湾、多个树丛 |
| 大岛 | 1400–2200m，约 5% | 偶发探索区域，另外限制面积占比和连续出现次数 |
| 相邻水道 | 岸线到岸线约 250–800m | 按巡航 46m/s 约为 5–17 秒；实际路线受岛形影响 |
| 沙滩 | 宽度约 20–60m，随海岸变化 | 湿沙、干沙、草边自然交错 |
| 地形高度 | 小岛约 15–60m；大岛初期不超过约 120–150m | 留出当前 240m 飞行高度上限内的机动空间 |

岛形由少量可控骨架（弯月海湾、狭长岛、双丘、偏侧树林）加低频变化构成，避免所有岛都是圆形噪声土包。草地与树林交错，保留空地和宽于飞机翼展的通道，不做均匀同心圆生态圈。

树冠用大块圆润形体与柔和明暗分组，细节主要放在轮廓和空隙；草地远处看大色块，近处才看草丛。避免高频色彩噪声、大理石纹、细碎写实高光和大面积透明叶片。昼夜分别调色，夜间仍保留地形与飞机的可读性。

## 4. 世界生成与共同数据源

### 布局规则

- 最小距离按岸线间的水道宽度计算，不能只比较岛中心。先用包围范围做快速筛选，再对候选轮廓检查。
- 最大距离约束岛群相邻连接，不是无限世界任意两岛之间的距离。仅用泊松分布不能保证最大空白距离。
- 先规划确定性的岛群连接骨架，再放入岛屿尺寸和轮廓；每个候选需满足间距、面积密度与可行水道。采样尝试次数有上限，失败使用满足约束的保守布局，不能无限重试或偷偷放宽硬约束。
- 明确岛群间是否允许更长海域：第一版默认仍通过相邻连接保持水道上限，不另设无限大空海区。
- 世界种子、岛 ID 与绝对坐标决定结果。布局不能随加载顺序或相机朝向改变；分块边界需查询邻域、使用确定性归属规则，避免重复生成或跨边界漏检。
- 已可见的岛不能移动或换形。返回旧区域保持地形与主要植被一致。

### 数据接口（拟议）

在 `src/land/` 内组织布局、地形采样、网格、植被、互动、粒子与流送；具体模块拆分按实现规模决定。

共享地表查询返回高度、法线／坡度、到岸线的有符号距离以及湿沙／干沙／草地／树林权重。统一用于网格、植被放置、飞行离地高度、相机避让、粒子类型、海岸浅水与浪花。

CPU 保留可用的高度与生态数据，不依赖逐帧 GPU 读回做避障。渲染网格、查询采样与 LOD 插值之间要控制误差并留安全余量，避免视觉地面与碰撞地面不一致。

地形表面数据跨块一致；植被通过稳定候选 ID 和空间归属去重。不能仅靠每块独立随机数制造边界断带。LOD 接缝方案必须明确，不能重现海面环接缝的亮线。

## 5. 草木互动与粒子

- 基于飞机离地高度、速度、航向与横向距离计算局部影响。使用前后帧之间的扫掠航迹，避免高速或低帧率时漏掉一段草。
- 草根固定，草尖向航迹两侧弯曲，经过后有延迟与阻尼回弹；植株大小和相位少量变化，避免整齐同步。
- 树干根部稳定；树冠／枝条偏转幅度小于草，小树可更明显。第一版不做逐枝刚体物理。
- 自然风覆盖全场，但飞机影响只在附近计算。优先用着色器内的有限航迹段实现；只有需要长期压草或多影响源时再引入局部 GPU 交互场。
- 粒子按地表类型发射：草叶、树叶、沙粒使用不同形状与运动；湿沙明显减尘。按经过距离／时间累计发射并设置单帧、总存活数量上限，防止低帧率补发爆量。
- 固定容量池，GPU 更新粒子位置、速度、年龄；有外力衰减与生命周期，不无限堆积。叶片使用实例化小几何体或四边形；不要依赖 WebGPU 可变尺寸 Points。
- 沙尘以局部、贴地、少量为主，避免多层大透明面遮住飞机。降级时先减少粒子数量，保留弯草主反馈。

## 6. 性能架构与反射

- Worker 负责后台地形和植被数据生成；使用可转移缓冲区，控制主线程每帧网格接入与 GPU 上传量。设置待处理队列上限、取消与过期任务丢弃规则，快速转向时不持续生成已经无用的区域。
- 按空间块实例化草和树，先做块级视锥／距离剔除；不要整座岛塞进一个永远可见的大实例包，也不要每株草一个对象。
- 草木基础运动优先顶点着色器；粒子适合 compute。GPU 实例剔除、压缩可见列表与间接绘制留作有测量依据的增强项，不作为第一版启动前提。
- 若引入 GPU 剔除，主视角、阴影与水面反射各有可见性需求，不能把主相机可见列表直接用于所有视角。
- 控制透明叠加、材质变化、阴影投射与像素成本。草优先不透明简化几何体或必要裁切，树冠使用成簇体积；近处树可投影，草不逐株投影。
- 复用模型、材质、缓冲区和粒子池；共享资源由明确所有者释放。驻留区域和缓存有硬上限，长时间飞行后内存应进入平台期。
- 预加载距离包含最大速度下的生成、上传与预热耗时，并保留转向余量。360° 保留粗略远景，前方优先补细节；雾只能遮接入过渡，不能代替提前准备。
- 接入现有质量调节，避免新增控制器与已有单向降级器互相争夺。优先降远处草、粒子、阴影和反射成本，再调整分辨率；质量切换不能重生成岛形或突然清空近景。
- 陆地反射使用简化岸线和主要树冠代理，不包含草、落叶或沙尘。当前反射选择会递归包含被标记根节点的后代，所以不能把完整岛屿根直接标记为反射对象。
- 反射代理的独立注册、生命周期、主视图不可见但反射可见、实例矩阵更新需要单独核实。现有接口不是“标记一下就完成性能优化”。

## 7. 分阶段执行与预览门槛

### 阶段 0：基线与接入设计

读本交接和当前代码，保留全部已有工作。确认实际预览入口与后端，记录无陆地场景在昼夜、低空、转向与穿云时的开销；补必要的可观察计数。确定一个固定种子的单岛实验入口和陆地开关，不改变日常默认画面。

交付：基线记录、实际运行 URL、各效果开销与暂定容量预算。尚无目标实机则明确标记，先在现有设备做可比较的相对测量。

### 阶段 1：单岛地形、沙滩与飞行安全

实现确定性地形与生态查询、分块网格、沙滩／草坡材质及海岸衔接。少量树冠占位用于构图，不铺满草和粒子。接入地形离地高度和相机避让；默认采用柔和的安全净空，不突然抬升镜头，也不强行接管全部飞行控制。扫掠／前视查询与最终防穿约束共同防止高速钻山。

初期用稀疏树林和明确通道；实体树干碰撞暂不作为完整玩法实现，但必须说明体验限制。地形最高点与飞行上限要留净空，无法满足时应限制生成参数。

交付：沙滩、草坡、树林占位的单岛可飞预览；日出／正午／夕阳／夜间截图；低空、爬升、俯冲、相机转向不穿地；海岸无亮缝、悬浮和明显水陆穿插。先评审轮廓与调色再扩细节。

### 阶段 2：植被和飞机互动

按块实例化正式草与树，加入自然风、扫掠航迹影响、回弹；再加入有容量限制的草叶、树叶、沙粒。完成电脑与手机基础档配置，保留主要互动而减少远景成本。

交付：掠草、掠树冠、掠沙滩三条固定路线；无同步整片弯折、帧率相关发射爆量或透明尘幕；记录新增耗时、绘制量、存活粒子与上传峰值。

### 阶段 3：岛群、流送与陆地倒影

从固定的三座小岛加一座大岛测试布局，再扩展为有界驻留、确定性区域生成。实现岸线间距约束、邻区检查、异步加载与回收；加入简化陆地／树冠倒影，单独核算反射成本。

交付：可持续飞行的岛群预览；快速转身四周有连续远景，岸线不会在近处突然弹出；返回岛屿保持一致；近岸倒影柔和稳定，不能显著抬亮整片海；生成失败与队列耗尽有可观察结果。

### 阶段 4：实机性能与回归

在明确型号的低端电脑和高端手机上，使用同种子、相同时刻与路线测试。热机持续飞行、快速转向、反复跨区、昼夜切换均需覆盖。按实测调整密度、内部渲染分辨率、阴影与反射；仅在 CPU 提交或可见性计算确实成为瓶颈时再做 GPU 剔除／间接绘制。

交付：设备／系统／浏览器表、60 FPS 目标是否通过、30 FPS 保底是否触发、稳态与加载尖峰、驻留资源趋势。没有实机数据不能将阶段 4 标为完成。

各阶段结束都提供当前可访问的完整预览 URL，并确认服务运行。截图只是辅助，不能代替可操作页面。用户反馈形成下一阶段输入，避免一次合入所有视觉变化。

## 8. 验证重点

- 必要的纯逻辑测试：固定种子与加载顺序一致性、跨区边界、岸线间距及失败回退、地形查询与网格一致性、航迹扫掠、粒子容量、过期任务丢弃和资源回收。
- 必要的视觉与操作检查：岸线／LOD 接缝、昼夜色块、草木形体、弯草回弹、透明叠加、飞机／相机净空、转身加载、反射可见性与遮挡。
- 性能测量必须启用真实海、云、飞机、后处理和实际所选反射；固定画面诊断与持续飞行分别记录。无头浏览器截图不能证明手机 GPU 表现。
- 每阶段运行相关测试与 `npm run build`；全局接口或飞行逻辑变更时运行完整 `npm test`。只写文档不必重跑图形测试。
- 陆地关闭后应保持当前海空玩法和已接受视觉，无需绑定历史提交的逐字节截图；陆地开关用于同条件 A/B 测量。
