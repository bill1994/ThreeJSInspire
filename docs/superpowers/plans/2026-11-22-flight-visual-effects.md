# 计划二 · 俯冲动态模糊与近水画面表现

**已实施，已完成桌面 WebGPU 验证，手机真机待测。** [执行记录与画面对照](../reviews/2026-11-23-flight-clouds-water-and-atmosphere.md)。 本计划包含俯冲动态模糊、局部水面高度图和深度交界泡沫三项交付。可先独立做俯冲画面对比，再接入水面与岸线。飞控、贴水轨迹、基础岸线遮罩和水花素材沿用[第一份计划](2026-11-22-flight-feel-clouds-and-water.md)的工作。

## A · 俯冲动态模糊

**画面目标**。刚压低机头时仍能认出远岛。随着下降率和空速同时升高，两侧近景出现顺着飞行方向的短拖影。开始拉平时迅速恢复岸线和水纹的清晰度，机身与翼尖全程可读。

- 复用第一份计划的空速和实际下降率。当前镜头用的俯冲系数在约 30° 低头时已满，单用它会让浅俯冲和高速深俯冲过于相似。给模糊量加平滑起落，在触水时间缩短或玩家开始拉起时提前回收。
- 第一版试**有方向的屏幕边缘模糊**。以航向在画面上的消失点确定方向，近景较强，地平线与远云较弱。用飞机的屏幕投影覆盖完整翼展；读取邻近颜色时也排除机体像素，防止红色机翼拖到背景。HUD 在画布上方合成。
- 试调起点为同一竖屏输出下，最外缘分别拖长 0、2、4 个显示像素，按画面短边换算到不同分辨率。先比较开启与关闭，再比较不同强度。保留独立关闭选项，低画质先走现有速度线与视场角反馈。
- 在已有 Bloom、DOF、SMAA 的图上比较合成顺序，重点看太阳反光拖尾、机翼边缘串色和景深叠糊。稳定后再组合计划一的机身轻颤与拉起反馈。若大坡度转弯时方向误差明显，可比较高画质运动矢量方案。[Three.js 运动矢量模糊示例](https://threejs.org/examples/webgpu_postprocessing_motion_blur.html)

## B · 局部水面高度图

**画面目标**。飞机在海峡贴水画 S 弯，旧波纹留在原来的水域继续扩散。越过旧航迹时，水面反光显出两组波纹的交叠。

- 消费计划一按距离记录的掠水落点、强度与左右方向。高画质先试一个以飞机附近为中心的低分辨率高度场，以双缓冲迭代传播和衰减。窗口平移按世界坐标保留重叠区域，重飞或传送时清除旧扰动。
- 将高度梯度接入近海法线，让反光与倒影局部弯曲。复用同一组落点协调泡沫和水花强度，飞离后等余波衰减再暂停更新。岸侧遮罩抑制源项及跨陆地传播，低画质保留基础航迹。
- 首轮比较 64² 与 128² 两档，再根据高速漏点、波纹寿命与手机帧时间选择覆盖范围和更新频率。验收包括直飞、S 弯、折返穿过旧航迹、贴岸转弯和重飞。[Three.js 交互水面示例](https://threejs.org/examples/webgpu_compute_water.html)

## C · 深度交界泡沫

**画面目标**。从高处能沿着碎浪读出海湾形状；下降到沙滩旁，会看到薄薄的沫沿真实水线断续聚散，潮湿的沙色还能从中露出来。

- 计划一的世界空间岸线遮罩给出大致范围、进退相位和远景碎浪。在近岸范围内，将水面与水后面不透明地形的深度换算到同一视空间，用小深度差生成较细的接触沫，按距离与原有浪带交接。
- 先确认读取的是绘水之前的地形深度。当前海面会参与主场景绘制，最终合成深度可能只剩水面自身。若现有渲染顺序无法提供合适输入，比较仅绘制邻近地形的低分辨率深度目标及其开销。世界空间遮罩继续过滤远岛和前景掠过造成的误判。
- 用低视角沿斜岸飞过，检查掠射角带宽、岛块接缝与远处水线闪烁。对比正午、逆光、夜景，保留泡沫的阴影色，近景加强细节后仍能分辨深色海水与浅色沙地。

## 组合试玩与取舍

固定同一条海峡、时段、分辨率和飞行输入，依次录制压低机头、俯冲加速、贴水转弯、拉起回看。保留基础版、各项单独开启版与组合版，试飞者分别判断加速从何时可感、何时敢拉起、回看时能否辨认刚飞过的弯。

用目标手机比较 P95 帧时间、最慢帧及首次启用效果的卡顿。分别记录巡航、持续俯冲、低飞近岸三段，验证关闭效果能省掉相应 GPU 工作。本文的拖影像素、纹理尺寸和质量分档均为试调起点，最终取值以同航线试玩和设备实测决定。
