# 2026-11-03 近景云壳融合（puff shell fusion）— 设计

> 本文是设计，不是计划。计划另写。实现前需要用户批准本文。
>
> 上游：`2026-11-02-puff-cluster-cloud-design.md`（下称「上一版」）。本文只动**几何**，
> 着色沿用 `aa4b1f4` 之后的四档硬切，不改。

## 0. 一句话

把一朵近景云从「一堆各自完整的球塞进同一个 mesh」改成「一张连续的闭合曲面，被扇贝边切出菜花轮廓」：轮廓不再读成一摞圆盘，团块层次改由色块边界承担，而不是靠球与球之间的几何缝。

## 1. 为什么

`aa4b1f4` 的提交正文已经把话说尽了：

> the lobe *geometry* is still a set of overlapping spheres, so a close silhouette reads as a pile of discs. Only the band flip along those seams is gone. Fusing the lobes into one continuous surface belongs in `puff-shape.ts`, not in the shader.

核实结果与这句话一致，并且能说得更具体：

**几何。** `src/puff-shape.ts:132-161` 每瓣 new 一个 `IcosahedronGeometry`，做完絮状位移和随机旋转后 `mergeGeometries(parts, false)`。这个「合并」是**顺序拼接顶点数组**，不是布尔并集——每颗球的面片完整保留在 mesh 里，球与球相交处的内部面一张没删。于是：

- 剪影是一串球冠首尾相接，近看能一颗一颗数出来；
- 球与球相交处形成折痕（两个曲面以一定角度相交），法线在此不连续；
- 内部面还占着顶点和填充率，虽然被深度测试挡住看不见。

**实拍。** `artifacts/cloud-audit/puff-v5-hero.jpg` 里三朵云都能直接数出球；球缝有暗槽。

**参考图。** `artifacts/cloud-audit/ref/centre_column.png` 是一根**整体**的柱状云，轮廓由浅圆弧串成扇贝边，内部只有水平大色带，没有任何「球」的痕迹。它的「团」是靠**平涂色块 + 干净遮挡**分出来的——这正是上一版 spec §1 的结论，本轮要把它贯彻到几何上。

**上一版 §4 的反目标是个真张力，必须在这里解决。** 上一版写「云变成浑然一体的一坨，瓣数不出来」算失败。但参考图那根柱子**就是**浑然一体的曲面，它的瓣感来自色块边界与轮廓扇贝边，不来自几何球。所以本轮的目标不是「保留球」，而是「保留瓣感、去掉球」。这两件事在参考图里本来就是分开的。

**`lobeShade` 会失去语义基础。** `src/puff-cloud.ts:207` 读 `lobeShade`，`src/puff-shape.ts:155-159` 写它，注释写的是「这一瓣是谁」。几何一旦融合，「瓣」这个对象在数据上就不存在了。这个属性现在承担团块深浅差（`PUFF_LOBE_SHADE_GAIN = 0.22`），必须重新定义，否则四档硬切会退化成一块没有层次的色板（上一版 §4 反目标第二条）。

## 2. 目标

- **G1 剪影**：近距离单朵云的轮廓是连续曲线，不得读出球冠串联或球面折痕。
- **G2 瓣感**：单朵仍能数出 ≥ 3 个团块边界（上一版 §9 验收 3 的延续），但边界不得与任何球轮廓重合。
- **G3 拓扑**：每朵云是一张闭合、流形、单连通的曲面，没有内部相交面。
- **G4 兼容**：`puff-cloud.ts` 的三件套（`DoubleSide` / `alphaTest` / `depthWrite`）与四档硬切一字不改就能用；`positionLocal` 的 `radial` 语义仍然成立。
- **G5 可复现**：同 seed 同几何，逐顶点一致；瓣数、摆位、缩放仍由种子驱动（上一版 §7 的纪律）。
- **G6 预算**：视锥内实际绘制的三角形增幅 ≤ 1.5×；帧间隔 ≤ 33.3 ms；构建耗时一次性 ≤ 500 ms。

## 3. 非目标

- **不追求参考图逐弧段 1:1**。本轮的门是「不读成球堆 + 瓣感还在」。弧段数、凹口深度的精确复刻留给后续（届时可能换方案 B）。
- **不改着色**。`PUFF_BAND_THRESHOLDS`、`PUFF_BAND_COLORS`、`PUFF_NORMAL_WEIGHT`、四档硬切全部保留。`PUFF_LOBE_SHADE_GAIN` 允许调整（见 §7），但分档结构不动。
- **不改散布、回收、白雾、变体配方**。`puff-field.ts`、`in-cloud.ts`、`PUFF_VARIANTS` 的数值不在本轮范围。
- **不改 dome**（`clouds-compute.ts`）与 `CLOUD_PALETTE`。

## 4. 反目标（技术做成了也算失败）

- 云变成一块没有团块的平色板（把上一版的病灶反向犯一遍）。
- 为了融合把轮廓磨圆成一枚鸡蛋——参考图的菜花边是设计目标，不是噪声。
- 引入写实向的噪声侵蚀、软边溶解、体积渐变。
- 同种子出不同几何，或构建耗时拖垮首屏。
- 为了省事把 25 朵减到 14 朵（上一版 §5.5 已签字 25 朵）。

## 5. 约束（不能动的东西及其理由）

### 5.1 三件套

上一版 §5.1 的三条（`DoubleSide` / `alphaTest = 0.02` / `depthWrite = true`）全部保留。融合后每朵云变成单连通闭合曲面，这三条的必要性只增不减：钻进云里仍会看到内壁，透明片元仍会写整片轮廓的深度。

### 5.2 阈值与配色单源

`PUFF_BAND_THRESHOLDS` 仍是 TSL 与 `puffBandIndex` 的唯一来源；`PUFF_BAND_COLORS` 是按渲染色反解的，**不许**为了让新几何好看而重解——如果新几何让云变亮/变暗，那是几何的法线或体积问题，不是色板问题。

### 5.3 确定性 RNG（以及一个必须承认的限制）

`mulberry32` 的调用序列是布局的契约。`lobes[]` 的生成代码**原样保留**，`rand()` 调用一个不动——同种子下每一朵云的布局与上一版一致。

**但整场位级一致做不到，原因要写清楚**：`initPuffClouds` 用**一个** `rand` 顺序造 25 朵（`src/puff-cloud.ts:243-263`），而每朵的消费量天然变长——瓣数 `n` 是随机的，`lobes` 循环消费 `1 + 5n − spine` 次，每瓣还有 6 次旋转/缩放，顶点色又是**每顶点** 1 次。新壳的顶点数与旧版不同（1245 vs 约 5940），这条链从第 2 朵起必然分叉。任何"保持消费量"的垫片都只能靠重跑一遍旧几何来空转，代价不值。

所以本轮不承诺「同一批云」，改为两条可执行的对照：

- **几何层面**：单测与探针脚本用**显式 `lobes` 数组**构建（不经 RNG），不受布局影响，可逐位复现、可回归。
- **视觉层面**：同机位、同种子、`?puff` 开关，比的是**统计指标**（碎边组件数、画面占比、色阶数），不是逐像素 diff——云不同不影响这些指标的含义。

新增的壳细分与求交**不消耗 `rand()`**（icosphere 确定性，絮状位移用位置哈希），这一条仍然成立。

> `src/puff-shape.ts:94` 把 detail `clamp` 到 `Math.min(3, …)`——现状 `PUFF_DEFAULT_DETAIL = 2` 对应每瓣 180 面。新壳的细分参数与它**不是同一个东西**，不要沿用这个 clamp。

### 5.4 预算

- 25 朵 / 25 份 material（上一版 §5.5，已签字）。
- 帧间隔 ≤ 33.3 ms。
- 现状几何：`IcosahedronGeometry(r, 2)` = 每瓣 180 面 / 非索引 540 顶点，约 11 瓣/朵 → 每朵约 1980 面 / 5940 顶点，25 朵约 5 万面 / 14.8 万顶点（索引化前）。
- 现状绘制三角形增量：9720（`artifacts/cloud-audit/puff-budget-2026-11-02.json`）。

## 6. 方案

### 6.1 选定：径向包络（方案 A）

一朵云改成一个 `IcosahedronGeometry` 壳，每个顶点沿自己的方向从云心射出去，求它打在「所有瓣的并集」上的半径，把顶点推到那个半径上。拓扑是一个球，几何是连续的。

**为什么这里能用闭式解。** 射线与球求交有解析根；n 个球的并集在「从云心出发的每条射线上」就是取最大的那个 t。不需要体素、不需要迭代、不需要 marching cubes——因为云的形状从云心看是星形的（竖直主柱 + 侧面凸瓣，没有悬垂、没有凹腔）。

**融合而不是硬取最大。** 硬取 `max(tᵢ)` 会在两球交界处留下折痕（正是现在球缝的成因，只是从"几何相交"变成"半径跳变"）。用 log-sum-exp 代替 max：

```text
tᵢ  = 射线(O, d) 与球(cᵢ, rᵢ) 的远交点（无交则 −∞）
tmax = max(tᵢ)
r   = tmax + (1/k)·ln( Σᵢ exp(k·(tᵢ − tmax)) )
```

性质：

- **恒 ≥ max**：交界处半径是鼓出来的，不是凹进去的——得到外凸的圆弧过渡，正是扇贝边；
- **k 控制融合宽度**：k → ∞ 退化为硬并集（折痕回来），k → 0 退化为平均（交界处被拉平，瓣感消失）；
- **O(n) 且确定**：每个顶点只做 n 次二次方程 + n 次 exp，无随机、无迭代收敛问题；
- **稳定实现**：先减 `tmax` 再 exp，避免 `exp(k·t)` 溢出。

**云心怎么取。** 不能用 bbox 中心（对 tower 这类高瘦变体会偏），用 `lobes[]` 的半径立方加权重心——体量大的瓣权重高，保证云心落在「看得见所有瓣」的位置。这是本轮唯一新增的几何量。

**原点约定（必须和着色、白雾对齐，否则会烧掉一轮调参）。** 现状 `buildPuffGeometry` 末尾是 `merged.center()`，即**包围盒中心**；而射线从质心 O 射出。tower 上这两点差好几米，直接后果是：

- `positionLocal` 的零点变成 bbox 中心，`radial = normalize(positionLocal)` 不再是「从质心看的方向」，赤道附近的 `radial·sun` 整体偏 10~25°，四档终止线跟着歪——**表现和「gain 调小了」一模一样**；
- `blobs`（白雾）用 `mesh.position` + bbox 反解的 `halfW/halfH` 定位穿云椭球，原点一偏，雾也跟着偏。

所以本轮定死：**几何原点 = 质心 O**（生成后减 O，不再调 `center()`）。连带处理：

- `blobs` 的 `x/y/z` 用 `mesh.position + 几何 bbox 中心的局部坐标`（bbox 中心相对质心的偏移，`buildPuffGeometry` 存进 `userData`），而不是裸的 `mesh.position`；
- `halfW/halfH` 仍取 bbox 尺寸的一半（尺寸不受原点选择影响）；
- 单测钉一条：`|bboxCenterLocal| < 0.15 × halfH`，防止原点约定被后人改回去。

### 6.2 为什么不是另外三条

| 方案 | 为什么不做 |
|---|---|
| **B. SDF + Surface Nets / Marching Cubes** | 质量上限最高，支持任意拓扑（凹腔、悬垂）。但代码量约 3×，构建要跑体素采样（慢一个量级），而本轮形状不需要任意拓扑。**保留为 A 实测失败后的退路**：若非星形吞瓣严重到影响剪影，再上 B。 |
| **C. Blender metaball 烘焙 GLB** | 质量最高、前端零成本。但破坏上一版 §7 的程序化纪律（同 seed 同几何），并引入资产管线与加载器改造。只在「必须逐弧段 1:1 贴参考图」时才值得。 |
| **D. 只改着色（SDF 梯度当法线）** | 最便宜，能消掉球缝上的明暗跳变，但**剪影不变**——而提交点名的正是「close silhouette reads as a pile of discs」。不解决目标问题。 |

### 6.3 参数与量纲

**detail 的语义是个坑，先钉死。** `THREE.IcosahedronGeometry(r, d)` 的 `d` 是**每个面的线性细分次数**，面数 = `20 × (d+1)²`，不是 `20 × 4^d`。实测（`artifacts/archive/puff-shell-fusion/shell-bench.mjs`）：

| detail | 面/朵 | 顶点/朵 | 25 朵构建耗时 |
|---|---|---|---|
| 4 | 500 | 267 | 89 ms |
| 8 | 1620 | 839 | 236 ms |
| **10** | **2420** | **1245** | **364 ms** |
| 12 | 3380 | 1731 | 473 ms |
| 15 | 5120 | 2619 | 742 ms（超预算） |

现状每朵约 1980 面（约 11 瓣 × 180 面）。G6 的 1.5× 门按**每朵面数**算，不看总 delta（总 delta 里混着视锥剔除，换个机位就变）：

| detail | 面/朵 | 相对现状 | 判定 |
|---|---|---|---|
| 8 | 1620 | 0.82× | 过门，但轮廓出多边形感 |
| **10** | **2420** | **1.22×** | **起步值** |
| 11 | 2880 | 1.45× | 上限 |
| 12 | 3380 | 1.71× | 过不了，除非先优化求交 |

**起步 detail 10**：2420 面（1.22×），25 朵构建 364 ms（在 500 ms 门内）。detail 12 只有在 §6.4 的两条剪枝把耗时压到 250 ms 以内时才值得考虑，且必须同时申请预算豁免。

- **k**：融合宽度，量纲 1/米。实测（bank，`shell-probe.mjs`）膨胀量随 k 单调下降：

  | k | 最大膨胀 | 占 lobeR | 包围盒 x 变化 |
  |---|---|---|---|
  | 0.30 | 4.25 m | 0.46 | +9.5% |
  | 0.50 | 2.42 m | 0.26 | +2.6% |
  | **0.75** | **1.50 m** | **0.16** | **+1.1%** |
  | 1.00 | 1.05 m | 0.11 | +0.6% |
  | 1.50 | 0.66 m | 0.07 | +0.2% |

  **起步 0.75**，可调区间 0.5~1.5。k < 0.5 会让云整体胖一圈（包围盒开始接近 15% 门），k > 1.5 融合基本看不见。

- **肩瓣可见性**：径向投影只保留「从云心可见」的部分。现有肩瓣落在 `|x| = (0.40~0.68)·halfW`、`|z| ≤ 0.25·halfW`，从云心看基本在可见锥内。**需要实测确认**；若某侧肩瓣被主轴吞掉，优先收窄 `|z|` 偏移，而不是挪云心。

### 6.4 可行性实测（已做，证据在仓库里）

写这份设计之前先跑了三个只读探针，结论如下：

1. **星形性成立**。四种变体、detail 4 的 1500 个唯一方向，**零个方向无交**——没有「从云心看不见」的瓣。方案 A 的前提在这个形状族上成立，不需要退到方案 B。
2. **融合确实消掉折痕**。`shell-plot.py` 的右列（半径随角度）里，硬并集（虚线）在球交界处是**直角折点**，融合后（实线）全部变成圆弧过渡。左列的极坐标剪影同向。图：`artifacts/archive/puff-shell-fusion/shell-fusion-probe.png`。
3. **包围盒几乎不动**。k ≥ 0.75 时 softBox 与 hardBox 各轴差 < 2%（§6.3 表）。融合不会把云吹胖。

复现命令：

```bash
node artifacts/archive/puff-shell-fusion/shell-probe.mjs bank 10 0.75 --dump
python artifacts/archive/puff-shell-fusion/shell-plot.py
node artifacts/archive/puff-shell-fusion/shell-bench.mjs 10 0.75
```

**构建耗时是当前唯一的硬约束**，且 bench 里是未优化的实现（每个顶点对每颗球都调 `Math.exp`）。落地时至少要加两条剪枝，否则 detail 12 也上不去：

- 只对 `tᵢ > tmax − 5/k` 的球做 `exp`（其余贡献 < e⁻⁵ ≈ 0.7%，可忽略），典型情况 exp 次数从 13 降到 2~3；
- 球参数放 `Float64Array` 平铺，避免逐次对象属性访问。

### 6.5 不规则性从哪来

现状的不规则性来自每瓣的三件事：絮状位移（`0.10·sin(px·0.55)·sin(py·0.75)·sin(pz·0.62)`）、随机旋转、逐轴缩放 0.94~1.08。**这三样全部与「球」绑定**，而闭式射线求交只描述未被揉过的正球——把它们塞进求交就失去解析解。

所以本轮把它们从「瓣内部」搬到「壳表面」：

- 旋转与逐轴缩放：**丢掉**（`rand()` 照常消费，见 §5.3）。融合后的曲面不需要每瓣各自的方向。
- 絮状：改成壳生成之后、沿径向的一次低频位移，振幅 ≈ `0.03~0.05 × lobeR`，用**位置哈希**驱动（`sin(dot(p, k))` 那类），不消耗 RNG。作用在最终曲面上，不影响求交。

这一条同时决定了剪影仅剩的不规则性来源——所以振幅不能设成 0，否则云会变成一枚数学球。

### 6.6 权重形式（L2 的另一半）

§7 的 L2 需要一个权重 `wᵢ`，而 `exp(k·(tᵢ − tmax))` 在 k ≈ 1/m 时**尖得离谱**：两球表面差 3 m，权重比就是 e³ ≈ 20，混合退化成 argmax，L2 当场变回 L1 的 Voronoi 边界。所以权重必须与融合参数 k **解耦**：

```text
wᵢ = exp( −((tmax − tᵢ) / σ)² )        σ ≈ 0.3 × lobeR
```

σ 决定「哪几颗球的 shade 参与混合」，典型只会留下 2~3 颗，过渡带宽度 ≈ 2σ ≈ 0.6·lobeR——比 k 的融合带（~0.16·lobeR）宽，正好让 shade 边界落在球面交线**之外**，不形成球弧。

`shadeᵢ` 的取法：**用原始的连续值**（`hash01(i+1)−0.5)×1.6 + (y/halfH)×−0.35`），不要先 `round()` 再混——先量化会把高度项丢掉。混合后得到的连续 shade 直接写进顶点属性，量化留给片元（§7）。

## 7. 与着色的接口：`lobeShade` 重新定义

这是本轮最容易做砸的地方，单列一节。

融合后没有「瓣」。但 `PUFF_LOBE_SHADE_GAIN = 0.22` 的团块层次必须有人接盘，否则四档硬切会退化成平色板（反目标 1）。三个候选：

| 候选 | 做法 | 风险 |
|---|---|---|
| **L1 主导球** | 每个顶点取权重最大那颗球的 shade | 分界线是「哪颗球主导」的 Voronoi 边界，形状接近球面交线 → **还是读成球**。否决。 |
| **L2 权重混合**（推荐） | 连续 shade 写顶点属性，**量化留给片元** | 边界是片元级等值线，沿形状的肩部走，不形成球弧。 |
| **L3 高度分层** | 按主轴 y 分 3~4 段取 shade | 边界是水平线，最接近参考图色带走向；但失去团块感，且与 `radial` 的明暗方向重复。 |

**推荐 L2，但必须修正一个致命细节：量化不许发生在顶点上。**

顶点属性会被三角形线性插值。如果按老做法把 shade 量化成 `{-1, 0, 1}` 写进顶点属性，那么边界要么在每条边上折一下，要么变成一个三角形宽的软坡——**这正是本项目当初把分档从顶点色搬进片元的原因**（`src/puff-cloud.ts:119-122` 的注释写得很清楚：顶点色分档的硬边界只能沿三角面拓扑走，近距离出多边形色阶）。重蹈一次就是白干。

所以 L2 的正确形状是：

1. **顶点属性存连续 shade**（float，值域约 `[-1, 1]`），由 §6.6 的权重混合得到；
2. **TSL 的 `colorNode` 里做量化**：`bandW = clamp(litW + quantize(lobeShade) · GAIN)`，其中 `quantize()` 用 `step()` 切三档（`< -0.33 → -1`、`> 0.33 → +1`、否则 `0`）；
3. 于是边界是**片元级等值线**，不沿三角形边走，也不与任何球轮廓重合。

**属性契约因此变了**：`lobeShade` 从「三档离散值」变成「连续标量」。`puff-shape.test.ts:36-41` 那条「量化成三档」的断言必须整条替换（不是改数字），换成「值域落在 [-1,1] 且出现 ≥ 2 个不同的值」这类语义断言。

**允许调整的量**：`PUFF_LOBE_SHADE_GAIN`（0.22 是按球轮廓算的，融合后边界变软，可能需要上调到 0.25~0.3；上限仍受「档 1 不得少于 16.7%」约束）。`PUFF_NORMAL_WEIGHT`（0.04 是为了压球轮廓折痕，融合后法线连续，可以上调，但**不许**回到 0.28）。

## 8. 验收

沿用 `artifacts/ghibli-audit/` 的抓帧与测量脚本，同机位、同种子：

1. **球堆感（主指标）**：`edge-loops.py` 量出的 `fragmented-edge components`。现状 320，目标 **≤ 20**；`hard-edge density` 现状 1.3%，目标 **≤ 0.3%**。
2. **拓扑**：新单测断言——每条边恰好被 2 个三角形共享（闭合流形）、顶点数与 merge 后唯一位置数一致（无内部重复面）。
3. **瓣可数**：同机位截图，单朵云能数出 ≥ 3 个色块边界，且**没有一条边界与球轮廓重合**（人眼复核 + `measure-ellipse.py` 的椭圆拟合残差）。
4. **bbox**：四种变体的包围盒与现状相比，各轴变化 ≤ 15%（外凸会让它略胖，允许；塌缩不允许）。
5. **确定性**：同 seed 两次构建，顶点位置逐位相等。
6. **预算**：视锥内绘制三角形 ≤ 1.5× 现状；构建耗时 ≤ 500 ms；帧间隔 ≤ 33.3 ms。
7. **回归**：`npx vitest run` 全绿；`palettes.test.ts` 的 ΔL* ≥ 15 与四档色阶断言不许动。

### 8.1 本轮允许修改的既有断言（逐条列明，批准本文即批准这些改动）

融合必然打断几条钉死的契约，藏着不说等于让 builder 猜。清单如下：

| 断言 | 位置 | 为什么必须改 | 改成什么 |
|---|---|---|---|
| `lobeShade` 量化成 `{-1,0,1}` | `puff-shape.test.ts:36-41` | 属性从「逐瓣离散值」变成「连续混合值」（§7） | 值域 `[-1,1]` + 至少出现 2 个不同值 |
| `lobeShade` 的 runs 段数 3~16 | `puff-shape.test.ts:22-34` | 融合后不存在「逐瓣顺序拼接」，顶点顺序不再按瓣分段，runs ≈ 顶点数 | **整条删除**，换成「相邻顶点 shade 差 < 0.5」（连续性） |
| `PUFF_NORMAL_WEIGHT === 0.04` | `puff-cloud.test.ts` | §7 明确授权上调 | 改成 `0 < w ≤ 0.2` 的范围断言 |
| `PUFF_DEFAULT_DETAIL >= 2` 与「tessellates every lobe」2.25× | `puff-cloud.test.ts` | `detail` 的语义从「每瓣细分」变成「整壳细分」，两者不可比 | 换成壳细分的单调性断言（面数随 detail 单调增） |
| bbox 高 < 240 且宽 > 20 | `puff-shape.test.ts:57-66` | 融合后包围盒变化 < 2%，**应当仍然通过** | 不改，但必须在验收时复测确认 |

**仍然冻结、不许碰**：`palettes.test.ts` 的 ΔL* ≥ 15；`PUFF_BAND_THRESHOLDS` 与 `puffBandIndex` 的镜像断言；`PUFF_BAND_COLORS` 的间距与单调性断言。

## 9. 实现顺序（给 builder 的骨架，不是计划）

1. **壳函数先落地**：新增「输入 `lobes[]` + 云心 O，输出壳几何」的纯函数，与 `buildPuffGeometry` 解耦。内部顺序：`IcosahedronGeometry(1, detail)` → `mergeVertices`（**必须**，非索引几何既没法算法线也没法断流形）→ 逐顶点 log-sum-exp 求交 → 减去 O → 位置哈希的絮状位移（§6.5）→ `computeVertexNormals`。单测只测它：流形、确定性、bbox、原点偏移。
2. **接入**：`buildPuffGeometry` 保留 lobes 布局与 RNG 消费序列（§5.3），末尾换成调用新函数；`userData` 里带上 bbox 中心相对质心的偏移（给 §6.1 的 blobs 补偿用）。
3. **`lobeShade` 连续属性**（§6.6 的权重 + §7 的顶点侧），并替换 `puff-shape.test.ts` 里那两条断言（§8.1）。
4. **TSL 侧量化**：`puff-cloud.ts` 的 `colorNode` 里对 `lobeShade` 做 `step()` 三档，再乘 gain。这一步**必须**和 3 一起验，否则会看到「顶点色分档」那个老毛病回来。
5. **blobs 原点补偿**：`initPuffClouds` 的 `blobs` getter 加上 bbox 中心偏移（§6.1）。
6. **视觉一轮**：同机位抓帧，跑 `edge-loops.py` 量 1 号指标。这一轮决定 k、detail、gain。
7. **调参收敛**：k（0.5~1.5）/ `PUFF_LOBE_SHADE_GAIN`（0.22~0.3）/ detail（8~11）三选一。
8. **全量验收**：跑 §8 全部七条 + §8.1 的断言改动清单。

## 10. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| **非星形吞瓣** | 某侧肩瓣在融合后消失，云变瘦 | 收窄肩瓣 `|z|` 偏移；必要时把云心沿 y 微调。**不要**为此上方案 B。 |
| **构建耗时** | 25 朵 × 15360 顶点 × 13 球，首屏卡顿 | 逐朵 yield（现有 async 循环已有）；仍超 500 ms 则降 detail 到 3 并复核剪影 |
| **交界处过度膨胀** | log-sum-exp 让整朵云胖一圈，bbox 超 15% | 调小 k，或对 r 做一次 `min(r, 硬max + 上限)` 钳制 |
| **团块边界仍读成球** | L2 的等值线退化成球面弧 | 改用 L3（高度分层），或把 lobeShade 的量化粒度做粗（相邻两球共享一档） |
| **顶点分布不均** | 柱状云侧面/顶面的三角形被拉长，出现多边形感 | 升到 detail 11（上限，见 §6.3）；或对壳做一次切向 Laplacian 松弛 |

## 11. 留给 builder 的

- k 的具体值与是否逐变体不同（起步 0.75，见 §6.3）。
- detail 最终取 8 / 10 / 11 哪一档（起步 10，见 §6.3 的表），以及是否需要 LOD（按上一版 §12 的纪律：先测后定）。
- `lobeShade` 最终选 L2 还是 L3；L2 的量化阈值（默认 ±0.33）与 σ（默认 0.3·lobeR）。
- `PUFF_LOBE_SHADE_GAIN` / `PUFF_NORMAL_WEIGHT` 的新值。
- 顶点色 `color` 属性：**本轮保留不动**（`src/puff-cloud.ts:180` 已把 `vertexColors` 关掉，它是死数据，但删掉会改变 `rand()` 消费量，破坏 §5.3 的 A/B 对照）。清理是后续独立的小活，别混进本轮。

## 12. 明确不做的事

- 不引 Marching Cubes / Surface Nets 依赖（除非 A 被实测否决）。
- 不引 Blender 烘焙资产。
- 不改单面渲染、不关深度写入、不做预乘 alpha（上一版 §5.1）。
- 不把云压成鸡蛋、不做软边溶解、不做噪声侵蚀。
- 不为融合而减少云的数量或材质份数。
