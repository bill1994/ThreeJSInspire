## 0. 为什么现在做这件事

P1 交付了一个**能跑、能量测、可调**的体积云：`coverage 29.79%`、`tone_span 0.327`、30 秒帧间差 3.16/255、桌面 p95 20.9 ms。独立复审修掉 2 个 Critical 后，云的密度感明显上来。

但它**仍然是平滑的一条带**。P1 的验收标准里没有「好看」，所以这不是失败——是范围结束的地方。这份文档处理范围结束之后的事。

## 2. 目标 / 非目标 / 反目标

### 目标

1. **读起来是云**：有明确的团块、有暗底、有迎光的边。
2. **「一层层」可见**：垂直方向至少两条可分辨的密度峰。
3. **光照可信**：太阳项与 `ambient` 同量级，云底暗、边缘亮。
4. **两套看法可切**：`soft`（连续）与 `flat`（四档、柔边），同一套密度、同一个材质。
5. **两套都能跑**：桌面 high 不降档；手机 low 待真机测。

### 非目标

- ❌ 不做穿云、不做云影投地、不做天气系统。
- ❌ 不重写管线：仍是 TSL slab raymarch + 三层密度。
- ❌ **不把 flat 做成硬边**（用户拍板：只压颜色，边保持柔）。

### 反目标（做出来就算失败）

- **四档糊**：量化了颜色，但云还是糊的——等于给薄纱上了四个色号。
- **切换让云变形**：两档之间密度/轮廓不一致，切换像换了另一朵云。
- **边缘梳齿**：量化在云的半透明边缘产生阶梯或色带。
- **手机掉出 30 fps**。
- **两层云打架**：穹顶云和近景 puff 的色语言不一致。

## 3. 约束（沿用 P1，未变的只列要点）

- three **0.186.0** · **WebGPU-only** · 竖屏 60° · `camera.far = 2000` · 云水平半宽 1800。
- **`SHAPE_SIZE = 96`**（P1 fix pass 从 128 降下来的，烘焙 440 ms）。
- 密度图**必须可平铺**：噪声周期整除边长（`SCALE0/1/2 = 2/4/8`）。
- 调色单源：`sky-track` 的 `cloudBands[4]` / `cloudHaze`；太阳色 `sunColorFor()`。
- 时间只吃 `elapsed`，冻结抓帧可复现。
- 两档共用**同一套纹理**，`setQuality` 不重烘。

3. 先做形状、再做调色的**顺序不变**（P1.5 先于 P2）。

## 5. 设计决定（本澄的判断，可推翻）

### 5.1 形状对比度（P1.5 第一优先）

三个旋钮，按影响力排序：

1. **coverage 阈值收窄**：`smoothstep(0.30, 0.46, weather)` → 更窄（如 `0.34, 0.42`）。让「有云 / 没云」更干脆，产生明确的云团边界。
2. **侵蚀权重下调**：现在 `(1 - detail) * 0.32`。降低它会留下更多实体；提高它会啃得更碎。**目标是「成块的瓣」，所以先降后调。**
3. **shape 层补 Worley**（P1 ruling 留的回补路径）：在 96³ 上，用 12 个细胞的 Worley 与值噪声混合（约 `0.35` 权重）。96³ 成本是 128³ 的 42%，加一层 Worley 仍可控。

**判定：`cloud_blobs`（面积 > 0.2% 云带的连通块）落在 3–8；边缘梯度 p95 同比上升。**

### 5.2 光照（P1.5 第二优先）

P1 的单次探针 → **沿太阳方向 3 次采样求和**作为光学厚度：

```
τ = Σ_{k=1..3} density(p + sunDir · k·Δ) · Δ · σ
T = exp(-τ)
```

`Δ ≈ 40 m`。成本：每步 +2 次密度采样（28 步 → +56 次）。**只在 `density > 0.12` 时才做**，空区域直接跳过。

`phase` 已经做过 ×4π 归一（P1 fix）。这一轮的判据是：**云带内亮度直方图出现暗底/亮顶分离**。

### 5.3 分层

在 shape 的垂直 profile 上叠一条低频调制，产生 **2–3 条密度峰**：

```
profile(y) = ceiling(y) · (0.72 + 0.28 · sin(2π · (3y + φ)))
```

`φ` 由 seed 决定，避免和近景云同相位。判据：**行亮度剖面局部极大值 ≥ 2**。

### 5.4 两套看法（P2）

同一材质里加 `uLook`（0 = soft，1 = flat）。**只改输出，不改密度、不改 alpha。**

```
flat:  rgb → 亮度 L → 按 4 个阈值量化 → 用该档的代表色回填
       alpha 保持原值
```

- 代表色取 `cloudBands[4]`（已有单源），阈值可复用 `PUFF_BAND_THRESHOLDS` 的**分位**思路，但**独立标定**——体积云的亮度分布和 mesh 平涂不是一回事。
- 量化只作用在**云的颜色**上，天空和近景 puff 不受影响。
- 抓帧开关：`?cloudlook=soft|flat`（照 `parsePuffVisible` 的写法加 `parseCloudLook`）。

**为什么放在输出端**：用户明确要柔边。输出端量化不会动轮廓，切换前后**同一个云的形状完全一致**——这样「哪种好看」的对比才是公平的。

### 5.5 验收方式

两档各抓一组：`?cloudlook=soft` / `?cloudlook=flat`，同机位同 elapsed，跑 `artifacts/dome-audit/measure.py`。

同一份量具同时服务两档，判据除了原有的 `coverage / tone_span / banding / drift`，新增：

| 新指标 | 含义 |
|---|---|
| `blob_count` | 云带内连通块数（> 0.2% 面积），目标 3–8 |
| `edge_grad_p95` | 云带内边缘梯度 p95，目标同比上升 |
| `row_peaks` | 行亮度剖面的局部极大值个数，目标 ≥ 2 |

## 6. 分阶段

**P1.5（先做）**：5.1 形状 → 5.2 光照 → 5.3 分层。做完之后云应该**先变得像云**，颜色仍是连续的。

**P2（后做）**：5.4 两套看法 + 量测对比。**必须等 P1.5 的形态立住**——否则就是给薄纱上色号。

两阶段共用一套密度与光照，P2 只加一个输出分支。

## 10. 风险

1. **Worley 回补可能不划算**：96³ 上形状分辨率下降，加 Worley 可能只多噪点不多结构。**先试 5.1 的 1+2，再决定要不要 3。**
2. **量化在柔边处最容易出问题**：四档之间的过渡如果落在半透明边缘，会出现「色带描边」。需要 dither 或让量化阈值随 alpha 收窄。
3. **3 步 light march 的成本**：+2 采样/步，可能让手机 low 档掉帧。要有「high 才做」的开关。
4. **手机仍未测**：这一轮必须补，否则门 7 又只有一半。

## 11. Builder 复审回收（2026-11-10）

复审提了 7 条。以下 4 条**由本澄定案**并写进本文；剩下 3 条只有用户能答，见 §12。

### 11.1 定案：flat 量化的是「光照项」，不是输出亮度

原 §5.4 写「rgb → 亮度 L → 四档」是**错的**，照做会得到两类失败：

- 穹顶的 `ambient` 带 `heightMix` 高度斜坡，量化输出亮度会先切出**水平色阶**（竖着分档），和 puff 的「受光/背光」分档方向正交——正好撞反目标「两层云打架」。
- 半透明合成里，四档色会乘 alpha 再和天空混；alpha 落在 0.2–0.4 时，四档被天空稀释成一片=「四档糊」。

**改为**：量化作用在**光照权重**上（与 `puff-cloud.ts` 的 `puffBandIndex(sunW)` 同构），档位色仍取 `cloudBands[4]`。
**并且不动 alpha**——用户要的柔边与「切换不变形」都靠这条守住。

### 11.2 定案：门 4 必须可证伪——加 `?sunoff=1`

现在从一张截图里量不出「太阳项占比」。加一个 QA 开关把 `uSunColor` 置零，同机位拍 sun-on / sun-off 两帧，差值就是太阳项的真实贡献。**这条比任何形容词都可靠。**

### 11.3 定案：分层先做调制，出不来再拆 deck

复审说得对：相机在云下、射线贴着云走，`sin(3y)` 的剖面很可能被沿程积分抹平。
**决策树**：先上 §5.3 的 profile 调制；若 `row_peaks` 仍 < 2，再升级为「把单层 slab 拆成 2–3 个带真空隙的 deck」。后者要动 `DOME_SLAB` 的契约并重算步长预算，**不在第一轮**。

### 11.4 定案：drift 区间降级为「体检带」而非硬门

边缘变硬后同样的漂移会让帧间差变大。P1 的 2–12/255 是给薄纱标定的。
**处理**：形状定稿后重标一次，之后再谈区间；本轮只要求「非静止、无跳变」。

### 11.5 顺带修掉的 P1 缺陷

复审发现 `setQuality(false)` 只写 `uSteps`，`uOctaves` 从初始化后再没被写过——**low 档仍在付第二个 detail octave**（每步 4 次 3D 取数）。这是 P1 的 bug，本轮第一件事修掉。

## 12. 待用户拍板（3 条，会改计划）

1. **手机真机谁跑、跑不跑得成。** 本环境无 Android 设备；若拿不到，门 7 手机那半只能记 N/A 或用「桌面 low 模拟」替代，并据此设 light march 的预算上限。
2. **60 m 巡航几乎看不见云，要不要降云底。** 现在只在仰角 21°–30° 可见；降到 ~300 m 会连带改 `DOME_SLAB.base` 的三处契约（ALT_MAX 余量、`boxScale()`、`fadeEnd === halfExtent`），是 P1.5 里多出来的一个几何任务。
3. **DOF 糊云这轮修不修。** 桌面 high 的 DOF 会把整层云按最大 CoC 糊掉，并会把 flat 档的档边界抹成渐变——**在验收机上肉眼定夺 soft/flat 会失真**。要么本轮排一条修法，要么把所有美学判断钉在 `?post=0` 直出帧上并承认「验收帧 ≠ 成片」。
