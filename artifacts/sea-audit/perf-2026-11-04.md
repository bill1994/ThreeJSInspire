# Sea FBM 性能报告（plan Task 5，2026-11-04）

## 测量环境（冻结声明）

- 无头 Edge `--headless=new`，WebGL2 后端（headless 拿不到 WebGPU adapter；同一套 TSL 代码路径，符合 Global Constraints）
- **SwiftShader 软件光栅化**：像素成本发生在 CPU 侧，`gl.finish()` 同步后可测，但绝对值与真实 GPU 不可比
- 640×360（1280×720 的 FBM 帧在软渲染下每帧秒级，30 样本超时）；相机 alt=7 掠海、`?qa=frozen`、同一状态
- 测法：`qa.step(1)` 墙钟 + `gl.finish()` 强制同步（10 样本中位数）。rAF 中位数被 60 Hz 垂直同步钉死在 16.7 ms（实测），测不到片元成本——计划预判的口径坑，已绕开

## 结果

| 口径 | `?sea=fft` | `?sea=fbm` | 差 |
|---|---|---|---|
| 帧墙钟中位（640×360，SwiftShader） | 0.80 ms | 1.00 ms | **+0.2 ms（相对 +25%）** |
| 帧墙钟 p90（纹理刷新帧） | 7.5 ms | 6.4 ms | 噪声 dominated |

## 结论与限制

1. **相对值：FBM 色带使帧成本 +25%（软渲染口径）**。真实 GPU 上该差值预计更小（片段 ALU vs 带宽主导），但**绝对门「≤1.5 ms @1080p 真实 GPU」在本环境无法验证**——headless 无 WebGPU/独立 GPU adapter，判 INSUFFICIENT_EVIDENCE（threejs-visual-validation 口径）。真机复测时沿用本文件的冻结协议即可。
2. **降级**：`setQuality(false)` → FBM octaves 4→2 + FFT 纹理 128→64（`__porco.setQuality` 已暴露，一行）。低档调试视图（`fbm-debug-lowq-2026-11-04.png`）：色带更平滑但仍为长条，未回斑块 ✓。
3. **WebGL2 对拍**：本报告全部帧即 webgl2-TSL；WebGPU 侧同帧对比 INSUFFICIENT_EVIDENCE（同上）。
4. 泄漏检查：`dispose()` 后 `scene.children.length === 0` 由既有测试覆盖（`world.test.ts`）；新增无独立纹理资源。
